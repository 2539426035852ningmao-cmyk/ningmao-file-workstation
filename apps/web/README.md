# 柠猫 Transfer · Web MVP (W0–W2 候选)

## 自托管临时互传区

用 Node.js 22.13+。在 `apps/web` 下执行以下命令，使用专用空目录保存房间、成员及临时文件。

```powershell
npm install --no-audit --no-fund
npm run build
$env:ROOM_DATA = Join-Path ([IO.Path]::GetTempPath()) ("ningmao-rooms-" + [guid]::NewGuid())
npm run start:rooms
```

打开 `http://127.0.0.1:5176` 即可建区。已经有自建 HTTPS 站点时，直接打开其首页即可，网页用户只需要浏览器。网页发起后，复制邀请给 Windows 使用者，对方在「临时互传区」粘贴加入。开启审批时由群主批准。接收方点击保存并校验文件。

进入房间后，可以浏览或拖入一个文件，在发送前核对缩略图、大小和收件范围。分块站点支持勾选指定成员。共享列表显示发件人、有效期和本次页面里的领取状态。手机端先点「准备保存」，校验通过后再点「保存」。「已交给浏览器保存」表示下载已交由浏览器处理，可在浏览器的下载记录中查看结果。图片小图仅使用当前页面中已选取或已取得的本地副本。

独立客户机测试时，为自托管站点配置两端信任的 TLS 证书。用 `ROOM_TLS_CERT`、`ROOM_TLS_KEY` 指定文件，`ROOM_HOST` 指定测试网卡监听地址，`ROOM_PORT` 选择端口。邀请链接用两端均能访问且证书匹配的站点地址生成。SQLite 文件留在专用数据目录，其访问权限由站点运营者负责。本站点首轮以独立隔离环境验收，默认模式把临时文件存入 SQLite。分块模式把文件内容写入独立暂存目录，用 SQLite 记录进度和有效期。

默认每个文件最多 64 MiB，暂存总量 512 MiB。需要大文件时，启动前设置 `ROOM_BULK_QUOTA_BYTES` 为站点愿意提供的总字节数。分块模式单文件最多 20 GB，并受配额和可用空间约束。小于 10 GB 的文件默认可领取 24 小时，最长可延至发布后 72 小时。从 10 GB 起默认 6 小时，最长可延至发布后 24 小时。网页端可用完整副本主动供件，站点负责发现来源及回退。[原生回环与双机证据](../../docs/project-status.md)

### 网页站点账号候选

启动上面的自建站点后，从互传区页首打开「账号」，可注册、登录、修改账号名和密码及退出。也可直接打开同一站点的 `/account`。账号数据保存在站点的 `rooms.sqlite`。非回环连接必须使用 HTTPS。

临时互传首页可直接创建新区或使用邀请加入。登录后，「最近文件群」按建群时间显示最近创建的四个可访问固定群。账号页会保留邀请返回入口，三套主题选择会在同一浏览器的站点页面间延续。

在「账号设置」点头像可选 24 个内置动物，或上传不超过 10 MB 的 JPG、PNG、WebP。上传前先预览居中裁切，站点只保存 160 像素的头像小图。头像会在本人、已确认好友及同房间的已加入成员可见的界面显示，可随时换回默认动物。

账号名在站点内唯一。改名保留账号 ID，改密撤销其他会话。Windows 从「更多操作 → 账户」可创建并登录、登录已有账号或以游客继续。可选择独立的本机工作区，符合条件时也可显式关联已有工作区。Windows 和网页均记住有效会话，Windows 还会带出上次成功登录的站点和账号名。

Windows 的「打开网页版」可继续使用当前账号。首次用空白浏览器配置打开时，核对账号名并点击「继续使用桌面账号」。同一浏览器已登录该账号时直接打开。已登录其他账号的浏览器保留其会话，可独立接收软件发来的邀请。

登录后从「好友与文件群」输入对方账号名发申请。获批后可打开私聊，或勾选最多四位好友创建固定文件群。网页和 Windows 使用同一会话及文件清单。固定群的移动端网页入口仍可通过邀请加入，审批沿用现有规则。文本保留 30 天，每个会话显示最近 100 条，文件继续按原时限领取。

### 群管理交接

群主在固定群的「文件群成员」中选一位管理员，再到「群管理交接」指定为备用管理员。当前站点在线时，指定人员可点「继续群管理」。此时审批、移出成员和代为管理文件由该管理员办理。群主身份保留。群主或值守管理员可点「交回群主管理」恢复通常权限。

已在隔离环境用合成数据验证站点级冷备恢复。同一个站点地址从不同目录重启后，旧会话、原群、已备份文字与小文件可用。自动把备用站点定位到另一台设备，以及生产环境中的主备隔离，仍需单独验收。测试脚本不会导出实际站点数据。

**设计规范：** [全项目 design.md](../../design.md) 为唯一规则源头；[Web UI/UX 实施指南](../../docs/design/WEB-UI-UX-GUIDE-2026-11-09.md) 用于本网页的组件选择、微交互和验收。未经检查不得自动引入展示模板或 Pro 代码。

此目录是柠猫文件工作站的**独立浏览器前端与信令服务**，不修改桌面端的 Tauri/SQLite/文件安全逻辑。当前不代表已部署、正式发布或已通过真实双机测试。

## 首版范围

- 已编写：浅白/深蓝/亮蓝三套完整主题、移动端响应式、文件拖入/选择、设备显示、接收确认、取消、传输任务和 SHA-256 验证。
- 已编写：Cloudflare Access JWT 验证、按账号隔离的 Durable Object 在线设备与 WebSocket 信令；WebRTC DataChannel 加密点对点传输。
- 限制：**同一个 Access 用户的不同浏览器**。单文件最大 64 MiB；接收后需主动点「保存」；浏览器刷新后暂不保留记录；尚无断点续传、TURN 中继、跨账号分享、Windows 桌面端原生桥接、云端离线寄存；跨不同网络可能因 NAT/防火墙失败。
- 不提供本地任意目录访问；不使用仓库历史 Debug 浏览器中继/固定密码；不上传文件内容到 Worker。浏览器端通过 SHA-256 校验后才提供保存链接。

## 本地开发

在 apps/web 目录运行：

```sh
npm install
npm run dev
npm test
npm run build
```

普通 Vite dev server **只有 UI 预览**，不会跳过账号验证，也不提供假设备/假登录。生产功能必须通过下述 Cloudflare Access 环境测试。部署配置中有故意的占位变量，未配置时 API 返回 401，避免匿名公网暴露信令。

## Cloudflare 部署步骤（需所有者明确授权）

1. 在 Cloudflare Zero Trust 建立 Access **Self-hosted** 应用，保护最终 Worker 域名（覆盖 `/api/*` 与站点）；只允许自己的邮箱或已批准的测试用户。
2. 将 `wrangler.jsonc` 的 `CF_ACCESS_TEAM_DOMAIN` 替换为 `<team>.cloudflareaccess.com`，`CF_ACCESS_AUD` 替换为该 Access 应用 AUD。该字段不是密钥，但不得提交任何真实用户密钥/会话 JWT。
3. 根据 Cloudflare 套餐/对象计费确认后，执行 `npm run deploy`。先选择可控测试域名和访问策略，不自动绑定正式域名、DNS、R2 或公开监听端口。
4. 两个独立浏览器用同一个 Access 身份登录网页；页面自动发现对方；选文件、选设备、发送、接收端确认，然后接收端点击保存。
5. 实际验收：Chrome/Edge 双端、Android Chrome/iOS Safari、不同网络，检查 SHA256、拒收、取消、断线、大小限制。仅手机模拟器不能当实机验收。

**安全说明：** Worker 对每个 API 请求都校验 Access JWT 的 RS256 签名、issuer、audience 和过期时间。Durable Object 只负责同一 subject 的设备列表及信令；不传文件字节。WebRTC 使用 DTLS 加密；首版公共 Google STUN 服务器可看到相关网络元数据。账号凭据由 Cloudflare Access 托管，不能使用普通 Vite 开发服务替代安全边界。

## 部署后验收矩阵

| 检查 | 预期 |
|---|---|
| 未登录访问 API | 401/Access 登录，不泄露设备信息 |
| 登录两个不同身份 | 相互不可发现，不可跨账号发送 |
| 同一身份开两个浏览器 | 双方出现在在线设备列表 |
| 接收端拒收 | 发送结束且不会落盘 |
| 发送端取消 | 不出现成功状态 |
| 文件损坏 | SHA 校验失败且不提供保存 |
| 64 MiB 以上文件 | UI 阻止发送 |
| 断开网络/关闭标签页 | 对方离线，未完成任务不可声称成功 |
| 真实跨网络 | 记录 ICE/是否直连、失败时明确 TURN 需求 |

### 在线设备与标签页
浏览器在线会话 ID 存于本标签页的 `sessionStorage`（刷新保留、不同标签互不抢占）；这只是路由标识，**不是安全配对凭证**。账号仍由服务端验证的 Access JWT 所属 subject 确定。传输期间禁用改名，避免重新建立 WebSocket 时中断文件。

## W4 禁止未经批准部署

真实 Cloudflare Worker 发布入口已改为 `npm run deploy` → `npm run preflight:deploy` → build → Wrangler。没有明确 `NINGMAO_W4_DEPLOY_APPROVED=YES` 就会失败。这个变量**不等同于已经创建 Access 策略**；仍需要仓库所有者先确认独立测试域名、整个网站保护策略、Cloudflare 账单与额度、回滚路线及后端的 JWT 有效性。

`npm run preflight:source`、`npx wrangler deploy --dry-run` 和 GitHub Pages W0 静态预览不需要这项部署授权。不得为了让 CI 变绿而伪造云端批准，真实 Access JWT 和云端令牌不能提交到公开仓库。
