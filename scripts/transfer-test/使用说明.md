# 柠猫互传首版验收

| 要测试的路径 | 入口 |
| --- | --- |
| 一台 Windows 上的应用与独立网页 | 双击「Start-Room-Host.vbs」，按下方启站。 |
| 电脑与 Android 浏览器 | 使用两端可信且可访问的自托管 HTTPS 站点，从「手机扫码加入」进入。 |
| 两台 Windows 的附近直传 | 文件架选文件后用「发送到设备」。收件端先选保存位置，再显式开启接收和确认。 |

## 软件发起，网页加入

1. 解压测试包，双击「Start-Room-Host.vbs」。这时只打开柠猫桌面，站点处于停止状态。
2. 打开「更多操作 → 临时互传区 → 本机互传站点」。选测试包里的 `test-data` 作为暂存位置，或选择一个专用的空文件夹。软件会在所选位置内创建「柠猫互传暂存」。选择文件暂存配额，点击「启动站点」。
3. 在已填入本机站点地址的表单写下「软件端」作为显示名称，保留「入区需批准」，点击「创建互传区」。复制邀请链接，在同一台电脑的浏览器隐私窗口粘贴打开，填写「网页端」并申请加入。回到软件批准网页端，再按下文来回收发。
4. 点击「停止站点」，验证网页无法刷新互传区。保留浏览器窗口，再次使用同一暂存位置启动站点，刷新原邀请。两端仍可访问有效期内的文件。保留浏览器窗口或使用原浏览器会话，才能沿用已有访客身份。

本机站点使用 `http://127.0.0.1:5192/rooms`，只供这台电脑使用。关闭软件进程时，本机站点会停止。原始文件、已收文件和站点暂存分开保存。测试包需要标准安装位置的 Node.js 24 和 WebView2。

## 网页发起测试

在一台 Windows 电脑上完成桌面与网页来回收发。双击「启动互传测试.vbs」，会打开柠猫桌面候选和一个独立的 Edge 窗口。测试站点地址是 `http://127.0.0.1:5186/rooms`，会随桌面候选退出而停止。

1. 网页的「显示名称」填「网页端」，勾选「入区需批准」，点击「创建互传区」，再点「复制邀请链接」。
2. 点桌面上的柠猫悬浮球打开文件架，再用「更多操作 → 临时互传区」。粘贴链接，显示名称填「软件端」，点击「加入互传区」。
3. 回到网页批准「软件端」。返回还开着的桌面互传区，获批后会自动进入。两端分别显示群主和成员。

## 手机扫码加入

在「临时互传区」选择「发起新区」，填写手机也能访问、证书受两端信任的自托管 HTTPS 站点地址。创建后展开「手机扫码加入」。手机系统相机扫码后，在浏览器填写显示名称并申请加入，回到软件批准，接着按下文双向收发。包内本机站点适用于同电脑的浏览器测试。

## 核对五人文件群

展开「文件群成员」，可看到群主、已加入成员和名额。等候批准的访客另列。群主和四名成员满员后，新来的第六个身份会收到满员提示。刷新、关掉网页或断网，会保留原有成员的名额。

要释放名额，成员可选择「退出文件群」，群主也可展开名单选择「移出」。原会话主动退出后可用邀请重新申请。测试多个身份时，用独立浏览器配置或不同浏览器，同一浏览器里的多个隐私窗口可能共享会话。

## 来回收发

1. **网页发给桌面。** 网页选择合成测试文件里的 `网页发出.txt`，点击「发给全区」。软件端打开互传区，文件会自动出现。把接收目录设为「桌面收件」，对该文件点击「保存」并确认。
2. **桌面发回网页。** 把 `软件发出.txt` 拖进桌面文件架并选中，用「更多操作 → 临时互传区」继续发送。网页「共享文件」中出现文件后点「下载」。桌面浏览器校验后会交给浏览器保存，手机先点「准备保存」，校验完成后再点「保存」。
3. **核对同名保护。** 可以先在「桌面收件」放一份同名的测试文档，再从网页发出该文件。桌面确认接收后应出现带编号的副本，两份内容都能打开。

## 中断与领取期限

- 网页上传中断后保留当前选择，连接恢复后可点「续传原文件」。刷新后可重新选择同一文件。核对共享文件里只出现一项。
- 桌面显示当前连接类型；断线期间暂停发送和保存。恢复后原邀请继续使用。也可点「刷新」检查站点状态。
- 文件行显示发件人和领取截止时间。默认保留 24 小时，达到 10 GB 的文件默认保留 6 小时。站点停机期间，重新连接同一暂存目录才能继续领取站点副本。已完成的浏览器会话可主动提供在线副本。

桌面和网页分别拥有独立的房间身份，邀请决定房间，审批决定访问权限。测试工作区、Edge 配置和站点数据集中在本包 `test-data`。本机已有的 Node.js 24、Edge 和 WebView2 会用于运行候选。启动失败时可查看 `test-data/launch.log`。
