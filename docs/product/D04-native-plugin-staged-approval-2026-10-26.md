## 2. 分阶段开放路线

### 阶段 1 · 安全接口与官方示范插件

只读取用户授权素材的文件名/类型等必要元数据、提出内部标签建议，必须经用户确认才写入柠猫内部标签；不需要网络、大模型或任意路径访问。优先复用已经存在的主程序 Store、任务中心及权限实现；如尚无此接口，先建立受控宿主能力代理。

可见的插件生命周期应能验证安装/启停/卸载、权限查看与撤销、异常隔离、升级兼容与回滚。**插件卸载不删除已确认的用户成果。**

### 阶段 2 · 受限第三方插件

在宿主能力代理、来源/完整性检查与真实撤权/隔离验收通过后，允许第三方以**受限、声明式或能力沙箱接口**扩展已授权的文件元数据/标签建议等明确范围。

自行导入、已验证、官方来源需要区分展示来源与权限，但任何来源都不能通过清单声明直接获得系统级全盘读写/命令执行；必须核查实现上的授权边界，而非仅以 UI 弹窗宣称安全。

### 阶段 3 · 原生高权限第三方插件（独立审核 Gate）

此阶段**不属于初始插件闭环的必须交付项**。先完成真实 Windows 原生进程/文件/网络权限边界与故障隔离研究，明确哪些风险能够可靠技术约束、哪些不能。再经单独安全审查与用户明确授权，才评估可执行原生扩展。

独立审批至少审查：可执行包来源/签名与完整性、执行边界、目标路径/操作级权限、联网与付费行为、权限撤销效果、升级扩权与降级恢复、失败时真实文件/用户数据安全、Windows10/11 兼容及审计/关闭入口。不能把“官方/审核”标签当成自动高权限；不能承诺进程隔离本身即安全沙箱。

## 3. 不可逾越的实施约束

- 安装、启用、工作流调用、更新、来源评级 **均不构成**系统高权限授权。
- 真实文件重命名、移动、覆盖、删除及本地原生命令执行需要相匹配的用户明确授权和必要的单独审批；云端出站或收费不能通过其他插件的许可继承。
- 不默认扫盘、不上传个人文件、不自动安装第三方二进制，不在双眼球、小文件架、Dock 加常驻插件按钮。
- 取消/卸载/崩溃后及时撤销宿主授权、停止任务并清理不需要的缓存；保留柠猫已确认的用户标签、虚拟名称及合法引用。
- 每一步使用**可运行 Windows 候选、具体权限/故障测试、源码 SHA、回滚策略**验收；不把文档、浏览器样机或未验证的沙箱概念当成插件已安全实现。

## 4. 下一步不是更多插件选择题

D-04 不应成为继续盘问已答 P4 29–39 的起点。P2 原生验收与安全合并 → P3 单/多文件 LAN → P4 本地搜索与可选 AI → P4 官方示范/受限插件 → 按技术证据评估原生高权限。
