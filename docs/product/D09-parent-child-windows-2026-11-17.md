# D09 父子窗口与底部状态横条

用户已逐项讨论并明确“方案确定开始实施”。基于D08/1302924，分支feat/parent-child-windows-20261117。本合同替代旧的独占拆出/关闭子架收成小球行为，不改变实体文件操作。

- 主窗口加号左侧放快速拆出当前架、全部收回两个统一图标。拆出同一份架内容的子视图，主窗口架、选择、检索、滚动保持；两边文件数据/标签同步。重复拆出只唤出已有子窗口。
- 最多9个不同架的子窗口，编号1–9。编号在打开期间及重启后稳定，收回后其余不改号，新窗口使用最小空号。主窗口另算。旧布局仍可解析，不截断文件架或数据库。
- 子窗口标题和主窗口切换菜单的子窗口区同时显示编号与名称，长名悬停完整。点击子窗口条目只唤出对应窗口；右侧×收回。普通架切换菜单选择后保持展开，外部点击/Esc关闭。
- 子窗口×或主窗口对应×只关闭/收回子窗口，不变球，不切换/唤出主窗口，不删除架与文件。全部收回沿用这些安全入口，失败保留真实反馈。
- 主窗口收起时一个共享球，子窗口暂时隐藏，记录仍为已打开；展开主窗口恢复子窗口的位置和大小。完整退出持久保存打开组合、编号与几何；重启仍先一个球，主窗口展开后恢复子窗口。
- 父子窗口各有32px固定空白底部横条，列表在上方滚动，底部左右圆角保持。本轮没有占位文案/虚构状态，也不添加联网/连接用户/数据采集。
- 子窗口视图偏好单独保存在ningmao-child-views，首次继承主架的已保存视图。主架原ningmao-shelf-views不迁移，切换子窗口列表/尺寸不更改主窗口外观。主题仍共享。

复用现有Tauri窗口、Radix菜单、Lucide图标、React与JSON布局/SQLite Store。无生产依赖、协议、数据库schema或真实复制规则变化。父窗可读取已开子架数据；子窗口仍只允许已登记架ID的文件/任务操作，保留Scope校验、投放冻结及进行中操作保护。

新编号布局写入desktop-layout-v5.json，按v5→v4→v3→v2→v1读取旧布局，旧文件逐字节保留，便于回滚旧候选。编号从旧未编号记录归一，不将新字段覆盖写入旧v4文件。
