## 下一阶段主攻问题

**第一门槛：真实 Windows 系统拖出 Copy、拖入与内部排序可以可靠共存，并且用户文件不能被移动或覆盖。** 现有技术探针曾实测，但 #9/#11/#13 各精确构建不继承此前测试结论。

**第二门槛：把主应用改回“小悬浮窗”，而不是将研究原型 1120×760 的全量工作台固定为日常主窗口。** 用户倾向小而精：默认建议 420×520，最小 340×320，最终依据真实截图及人工试用调整。优先单行顶栏、素材视图、按需搜索/详情/任务；把复杂功能送到独立管理中心。

代码审查还识别到两项需独立修复的交互偏差：
- `apps/desktop/src/App.tsx` 中 `onDoubleClick={inspect}`：冻结决策是双击用系统默认程序打开，Space 快速预览；需正确接入真实路径与失败提示。
- 当前主应用拖出常需经独立“拖出复制”入口，后续要验证是否可从文件项直接原生拖出，且不与 dnd-kit 手柄排序冲突。

## 推荐执行顺序（按关卡暂停）

1. **同步与审阅文档**：确认设计规范已进入默认分支，核实本次修订 PR 的检查结果；不得越过主分支保护。
2. **精确候选整理**：核对 #9 → #11 → #13 的堆叠分支与版本，明确哪一个 exe/msi 对应哪份源码，以及已测/未测。不得私自合并或安装。
3. **交互原生验收计划**：用合成素材编制一次集中的拖入、Copy 拖出、内部排序、关闭/恢复、系统选择器测试；用户方便时真实操作，不在用户使用电脑时弹窗、模拟输入或安装。
4. **紧凑 UI 独立实验**：以候选主工程为基础，另建 UI 分支，先做 340/420/640 宽场景与暗/亮主题；保持原生后端、数据库和安全测试不变；提供精准截图/短视频及可运行构建。
5. **关键用户反馈**：只问一个有决策价值的问题，收集真实软件截图或紧凑窗口参考图，锁定布局后再改正式窗口。
6. **验收后合并**：先守住安全/原生检查，再推进经人工批准的 PR；禁止把未验收 CI 当作安装或交互通过。
7. **能力推进**：核心收集/复制体验 → Dock/多架/管理中心 → 网络传递 → 授权 AI/插件能力；细节见 roadmap。

## 不能做的事

- 不修改用户其他仓库；不访问用户未授权目录，不上传私人素材、令牌或本地数据库
- 不擅自删除源文件、自动覆盖、把 Copy 变 Move、不自动扫描私人文件夹
- 不为了缩小界面删掉既定 43 项功能；应移动到按需入口
- 不在安全 Draft #9/#11/#13 中混入大规模 UI 结构重写
- 不把未来网络、AI 或插件“预留接口”包装为现有可调用功能
- 不未经授权使用鼠标键盘自动化、安装、强推、绕过保护或合并高风险 PR
