# P3 真实传输事件接入现有任务 Store（候选）

代码检查点 `b1b7311da2cb9ad9727afd055056f9fdb1245a1d`，基于 #53 的 `06758d7`。独立分支 `feat/p3-task-integration`，不改 main、不覆盖 r22、不放行 P2。

## 完成的实际闭环

受控发送/接收双进程执行 mTLS 本机回环，接收器按实际写入产生版本化事件。测试边读 JSONL 边调用桌面工程同一 `TransferTasks` 与同一 `Store`，写入真实 schema 2/WAL。管理快照中的状态和消息可读，未新建队列、数据库、WebView 权限或监听入口。此切片是内部适配层，尚未启用桌面网络任务入口及事件订阅，不能写成 GUI 联调完成。

事件只有独立随机任务标识、顺序、阶段、数量与字节；没有会话/上传令牌、证书、路径、地址或原始错误。任务标识与认证标识分别生成。进度按累计 1MiB 或 100ms 降频，取消优先；已收全字节仍可能校验失败，只有受保护发布完成才算完成。取消确认先记“等待安全清理”，清理/发布句柄退出后才记终态；发布与取消的终态在同一会话锁内串行。已终结任务不能被晚到事件改写。

适配器由可信 Rust 调用方选择既有文件架；跨架更新拒绝，重复事件幂等，同序号不同内容拒绝，越界/倒退/伪造早期完成拒绝。沿用 `queued/copying` 非终态以复用原有重启中断标记，不修改 Store、安全 Copy、文件身份或数据库结构。

## 本机验证

- Windows Rust：11 单元测试 + 4 Store 测试通过；其中一个默认运行真实双进程和 64MiB 流，11 个实际任务覆盖完成、部分完成、失败、取消。
- 实时读取到中间进度、校验和取消等待；完成/失败/取消只有一个终态。坏哈希批次保留成功的第一份，零字节文件成功；来源、旧同名目标、既有引用 ID/标签保持，临时文件清理。
- SQLite schema 2、`integrity_check=ok`；正常重开后终态记录完全相同。未终结任务沿用现有中断标记，不自动续传。
- fmt、全 targets Clippy（含同一桌面 Store）通过。测试先捕获两个实际失败，再补实现/场景；详见[脱敏证据](P3-task-store-evidence.json)。
- 独立 CLI SHA256：`085cef0e0c81e3793a2bb305276264a17c745aa7b983f1dfd04c7c07c9f5eec5`。这是实验 CLI，不是新的桌面产品候选，不替代 r22。

## 许可与构建

没有增加桌面发行程序的外部依赖；新增本仓库原创事件数据类型（Apache-2.0）。隔离测试复用桌面已用的 SQLite/image/base64，Windows 过滤 metadata 共 113 包，新增 29 个 registry 包都核查了包内许可文件；逐包名称/版本/许可/文件 SHA 见 JSON。保留既有 cap-std/winx LLVM exception 等义务；这是源码试验，未宣布发行许可最终放行。

C 盘不足 200MB，本轮编译/合成材料均放现有 D 盘试验目录；不删除旧环境、不移动用户数据。桌面完整编译交由本 PR Windows CI 核验，本机未重打 MSI。

## 未放行与下一关

没有真实 LAN/广播/防火墙、正式配对或官方 LocalSend 互通。没有在桌面 GUI 验证网络任务取消按钮。适配层当前只在受控测试中调用，管理中心原有“复制任务”文案和单活跃复制 Runtime 未改，避免把尚未接通的网络任务伪装成现有复制任务。

事件关联仅驻留内存，每个 worker 最多 64 任务；不自动重放旧日志。日志不构成文件发布与 SQLite 的原子事务，崩溃/磁盘耗尽恢复、持久化逐文件结果、重试关联及加入文件架尚待实现。正式 Runtime 启用前必须完成这些生命周期与取消路由检查，沿用现有任务列表，并完成 Windows GUI 验收。无真实网络权限时继续隔离验证，不默认启用监听。
