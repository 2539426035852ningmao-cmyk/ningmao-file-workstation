# 柠猫 Transfer · 成熟开源流程对照与闭环切片

> 2026-11-09；实现支线为 PR #79 的安全静态预览；真正联网 W1–W4 在 PR #80 中推进。本文件是**功能流程的行为借鉴**，没有引入或复制第三方源码、素材、品牌标识或商用组件。

## 参考项目与实际取舍

| 原项目及入口 | 成熟闭环的可借鉴行为 | 在本仓库的最小实现或约束 |
|---|---|---|
| [PairDrop](https://github.com/schlagmichdoch/PairDrop) | 选文件→发现设备/房间→对端接受→传输进度→下载；设备重命名、取消/离线提示、移动端路径 | W0 只补文件准备与清晰未连接态；W1 配对和 W2 WebRTC 保留真实后端验证。PairDrop 为 GPL-3.0，**严禁直接复制其源码**到 Apache-2.0 项目 |
| [LocalSend](https://github.com/localsend/localsend) 和 [协议](https://github.com/localsend/protocol) | 发送先给元数据，接收方接受或拒绝；跨平台文件目录归属、同名安全策略、移动端权限 | 既有 Rust Store/scope/jobs 与安全复制继续复用；接收不能由网页随意指定本机路径 |
| [FilePizza](https://github.com/kern/filepizza) | 浏览器点对点文件直传、发送端需保持页面打开、进度和取消、移动端支持 | WebRTC 与摘要校验保留在 PR #80；不复制 UI、服务 Worker、PeerJS/Redis/ZIP/Streaming 实现，复杂功能按需按 Gate 实验 |

## 用户可实际操作的阶段闭环

### 已开放的 W0 本地准备

1. 打开公开预览地址，选择浅白/深蓝/亮蓝任一主题。
2. 使用原生文件选择、拖拽、粘贴文件，或生成合成测试文件。
3. 去重并拒绝路径分隔符、保留设备名、控制字符等不安全文件名。
4. 搜索、按类型筛选、按名称或体积排序，显示总数量与容量。
5. 图片、音视频、文本内容可临时预览；不适合直接展示的文件只显示元数据。关闭时释放 Blob URL；纯文本使用有限读取且以纯文本显示。
6. 移除单个或清空全部，原始文件不受影响；刷新后列表清空且不持久化文件内容。
7. 清楚显示当前候选版传输限制（单文件 64MiB / 单次 16 项）和“服务未连接”的状态。**不能把本地准备显示为真正发送成功。**

这一闭环只验证 UI 与浏览器本地 File API，并不能完成设备间互传。

### 待通过安全 Gate 的联网完整闭环

- W1：登录→服务器核验 Access JWT→设备名与在线状态→安全配对/撤销（浏览器 localStorage UUID 不是可信身份）。
- W2：本机选择→实际在线设备→元数据邀请→接收方显式同意→WebRTC 数据→SHA256 验证→浏览器用户保存→真实任务记录。拒绝、超时、断线、取消不标成功。
- W3：Windows 文件架选择引用→Store/scope 授权票据→Rust 分块→安全信令→网页接收；反向为网页发送→Windows 接收方显式同意→安全暂存与哈希→现有安全复制/命名→jobs 终态。
- W4：HTTPS/Access/TURN/费用审批→真实 Windows/手机/不同网络合成文件测试→回滚演练；没做真实上线前不得宣称已联通。

## 明确未做 / 不纳入首版

离线长时网盘、公开匿名链接、强制安装 PWA、自动 ZIP、多 GB 整块入内存、服务器持久缓存和复杂表格看板。当前静态 Pages 只发布网页代码，没有连接外部云存储或收集文件。开源项目可参考流程但不能因为它们有功能就视为本仓库已经实现。

## 验收

- 运行 apps/web 下的 npm test、npm run build、npm run test:browser。
- 浏览器合成样例覆盖新增/去重/预览/移除/清空/筛选/排序、三主题、刷新、360px 移动导航及禁用发送/虚构设备。
- 不对用户真实文件使用 CI，只用内存合成素材。
- Pages 部署成功、访问 URL、设备两端传输等属于不同等级证据；必须分别记录。
