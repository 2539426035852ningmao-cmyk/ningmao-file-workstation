## 1. 产品目标：轻量、免费、即用即走

**用户只感受到：选择文件 → 选设备 → 对方确认 → 完成。**

- **默认免费**：P3 首发 LAN 传输不需要柠猫云服务器、会员、登录账号、云存储或额外付费 API；两台已联网设备间直接传输。没有新增服务账单，不代表用户完全没有设备、磁盘、电力、局域网或运营商计量流量成本。
- **简单直接**：正常用户只设置一次接收目录/设备身份，或在必要时选择目录；不把端口、TLS、组播、网卡、证书字段堆给普通用户。高级项只在故障或用户主动展开时可见。
- **最小常驻**：不默认扫描本地磁盘、不默认开机自启网络监听、不默认启动同步或云端上传。只在明确的接收授权和受限生命周期内启用网络服务；会话可停止并查看当前状态。
- **不强制账户**：局域网内设备名称可显示，但发现 ≠ 信任；首次配对/接收必须有清楚的确认，避免误发。
- **无自动付费退路**：无法直连时给出故障原因和可选择的连接方式，不偷偷启用或购买中继，不把开发者免费试用的公共 relay 当正式生产 SLA。
- **保留可靠性**：为简洁而隐藏常态说明可以，但不能隐藏真正的接收人、覆盖风险、文件来源、网络暴露、费用或失败状态。

### 范围

- P3-A：上游 Rust/协议隔离研究、可复现实验（不得影响正式 P2 代码及数据）。
- P3-B：两台 Windows 的 LAN 明确批准收发；官方 LocalSend ↔ 柠猫互通，然后柠猫 ↔ 柠猫。**首版只承诺此能力**。
- P3-C：异地直连/用户已有可信隧道为可选研究；NAT 可能无法直连。公共 relay 仅可作经单独同意的实验，生产服务和计费需另行批准。
- P3-D：目录同步与断点续传为后续阶段，不阻挡 P3-B 正式验收；不得默认启用。

## 2. 各 UI 区域的唯一责任（不重复功能）

| 区域 / 层级 | 必须承担的责任 | 明确禁止 |
| --- | --- | --- |
| **L0 双眼圆球 / 贴边柄** | 唤出、收起，**仅在传输发生时**显示一个低干扰状态点（需无障碍文本替代） | 常驻「发送」「接收」「设备」「设置」四个按钮；设备列表、进度百分比堆叠、网络诊断 |
| **L0.1 胶囊** | 当前架的极简状态；有任务时一行 `发送中` / `已完成`，用户点击进入对应轻预览或管理界面 | 进度条 + 大按钮 + 详细错误长文并排，展示敏感设备信息 |
| **L0.5 轻预览** | 展示少量当前文件与**一个情境操作**（如有选中文件时可 `发送`），正在发送仅提供折叠任务提示 | 作为第二套设备管理器、展示重复的「更多设置」 |
| **L1 日常小文件架** | 用户**先选择文件**，再在选中操作栏/右键菜单里出现一次 `发送到设备`；接收完成以短通知并可打开原架 | 默认工具栏永久加网络按钮；同时在顶栏、文件卡、底栏重复 `发送` |
| **Dock / 文件架投放区** | 继续承担**文件架归属、拖入本地收集、目标选择**。联网发送只能通过明确的模式/目标语义启动 | 靠近 Dock 就向远端自动发送；拖拽过程中悄悄切到网络模式 |
| **L2 按需管理中心** | 唯一完整的 `设备`、`传输任务`、`接收规则` 与 **高级网络排障**入口；首版无需独立网络主窗口 | 默认常驻；复制一份文件架；把网络设置当第二套 Windows 设置 |
| **系统授权弹层** | 仅在首次配对、首次监听、接收、访问受保护目录和明确改变信任时出现，显示必要风险 | 日常每传一个文件都重复冗长确认；后台静默扩大权限 |
| **L3 Rust TransferProvider** | 真正的身份校验、受限读写、加密、传输、SHA256、任务状态、取消和事务性保存 | 让 WebView/Orb 拿到任意文件系统、监听端口或密钥的宽泛权限 |

### 导航原则

- **一项任务只有一个主要入口**。已选文件：`发送到设备` 只在选中上下文暴露；没有选中文件：管理中心 `设备` 负责发起发现/接收，不制造重复空按钮。
- 发送设备选择使用**轻量弹层**：最多展示已信任设备与「查找附近设备 / 手动连接」；找不到设备时给一个明确故障入口，不展开所有调试参数。
- 网络任务沿用现有统一任务体系，**不新建独立传输任务中心**。常态只显示短状态，点击后管理中心查看详细速度、剩余时间、文件列表与失败原因。
- 长传输状态始终可找到；不能因为追求轻量隐藏可取消入口或把错误消失得不可追溯。焦点和键盘操作可达，禁用闪烁轮播。
- 文案尽量短：`发送`、`选择设备`、`等待接收`、`发送中`、`已完成`、`已取消`、`设备离线`；具体原因放在可展开的任务详情。
- 沿用 **现有图标、圆角、4px 间距、深浅主题、三色双眼球方案**，不发明 P3 专属皮肤/图标库、强制叠加动画、固定底部网络状态条。
- 紧凑窗口 **420×520 / 最小 340×320** 下优先保障文件区，不出现横向滚动；不用持久侧栏承载网络。
- 可用性：网络连接状态、错误及危险确认同时有文字/图标，不仅靠颜色；支持键盘、缩放和 reduced-motion。

## 3. 使用流程（默认不要求用户懂网络）

### 首次使用

1. 用户在文件架选择一个或多个文件 → 点击 `发送到设备`。
2. 仅此时出现紧凑设备选择弹层，优先展示曾授权的设备；附近发现需用户允许网络能力。首次需要的 Windows 防火墙行为作一次简短明确提示。
3. 选择对方设备 → 显示设备标识与将发送的文件总数/大小；身份尚未可信时要求核对指纹/等效可信身份。
4. 对端弹出单次接收确认，显示发送方、文件数量、总大小和接收位置（已授权目录可记忆）。
5. 开始流式加密传输、哈希核验、**不覆盖式**最终提交；接收完提示 `打开位置` / `加入文件架`（两个入口各自责任明确，主要动作优先 `加入文件架`）。
6. 用户收起窗口后仍可在状态点或统一任务中心找回任务；退出时按已批准的取消/保留规则处理，绝不悄悄丢失任务。

### 日常再次发送

只需 **选文件 → 选设备 → 发送**。已经明确配对的设备可以免去再次核对完整指纹，但**接收端仍需遵循用户选择的明确接收策略**；默认保留单次确认。不可将「配对过」等同于永久无确认自动收文件。

### 无法找到设备

- 轻量提示：`未发现设备`，下有 `重试` 和 `手动连接`，以及按需 `连接帮助`。
- 排障顺序：同一局域网 → 对方正在接收 → Windows 防火墙/端口 → VPN/AP 隔离 → 网络接口/手动地址；**不要求用户关防火墙**。
- 端口可配置，默认可参考 LocalSend 的 **53317**，但不能强行占用，也不得静默改防火墙。网络监听仅对明确允许的接口与周期有效。

## 4. 技术与安全合同（Rust 负责，UI 不感知协议细节）

- 候选：LocalSend Protocol v2.2 和 `localsend/packages/core`。上游 crate 默认 features 为空，**先按上游基线 `--features full` 检查、再隔离评测最小 features**；编译前锁 SHA、Cargo.lock、依赖许可证、安全记录；不得直接混入生产 Cargo.lock。
- 测试中可使用本机 loopback，但明确标为 LOCAL/SIMULATED，不冒称双 Windows 真机或 HTTPS/身份已达标。
- 文件读取只处理**当前授权的 FileReference / 所属架**，遵守现有 Store、Copy 与任务取消语义；不允许前端传入任意磁盘路径直接读写。
- 接收先创建限定目录下的临时文件，检查合法叶子文件名、路径穿越、Windows 保留名、重解析链接、配额、磁盘空间；**SHA256 通过后才以非覆盖语义最终提交**，保证已有目标不被中断破坏。
- 流式收发要有限内存、有背压与速率可观测，取消/磁盘满/连接断开时不会把部分文件当完整成功。局域网设备身份和 TLS 信任须单独验证，发现设备绝非认证。
- 多文件批次允许逐项成功/失败，但 UI 必须真实报告 `成功 N / 失败 M`，不能因成功一项便显示全部成功。
- 不对公网监听、不转发未经明确许可的本地文件、不把托盘驻留等同于可以永久网络监听。
- 若用户 P2/UI-B06–B07 的 schema2 回收和引用失效语义变动，**不得为了网络功能新建第二套资源身份或修改数据库导致旧用户数据无法恢复**；独立迁移与可回滚验收归 R3。

## 5. 零新增费用策略与成本边界

| 能力 | 用户可见费用默认 | 项目方后台设施 | 风险/限制 |
| --- | --- | --- | --- |
| 同 LAN 互传 | **无柠猫服务费** | 无集中转发服务器 | 使用已有网络与设备，可能有用户本身的网络/电力成本 |
| 手动地址 LAN | 无柠猫服务费 | 无 | 部分网络策略/防火墙可能禁止 |
| 基础设备身份与接收确认 | 无柠猫服务费 | 无账号服务器 | 需要本地保存可信状态和用户控制 |
| 异地用户自有 VPN/可信网络 | 柠猫不代扣费用 | 无 | 由第三方或用户自建网络的服务条款、容量、费用决定 |
| NAT 穿透、公共中继 | **非首发默认功能** | 不承诺免费正式中继 | 可能失败、限速、依赖服务运营方；不能依靠免费开发测试 relay 作为正式发布 SLA |
| 自建/托管商业中继 | 默认关闭，另行同意 | 可能有显著带宽/运维账单 | 必须单独公布成本、隐私、安全和资费，不得暗中启用 |
| 同步、云存储、AI | 均不是 P3-B 的必要前置 | 首版无 | 不自动注册、下载模型、上传文件或开通付费 API |

**项目预算 Gate**：P3-B 的设计与原型可以在既有开发资源上完成；未经批准不得新增域名/服务器/CDN/收费 API/托管中继/第三方计费账号。对终端用户不捆绑订阅。未来商业托管属于独立选项，不得影响基础 LAN 可用性。

## 6. 轻量和体验的可测试标准

Codex 每个完整候选检查：

- [ ] **正常无任务**：L0/L0.1 不出现网络按钮、数字仪表盘、网络长提示；L1 顶栏不新增常驻发送按钮。
- [ ] **单任务**：一个显著主操作路径，设备选择 ≤2 个常见动作，正常传输仅一处主状态反馈，可找到详细任务。
- [ ] **无功能重复**：设备管理只在 L2，文件发送只从选中上下文发起，Dock 不成为隐性远程发送入口。
- [ ] **布局**：340×320、420×520，深浅主题、150% DPI、键盘与屏幕阅读器可找到发送/取消；文件缩略图仍占主体面积。
- [ ] **轻量后台**：无任务/未允许时不产生监听端口、不启动大扫描、不下载模型；测量前后待机 CPU、内存、线程、网络流量和可执行包增量，**记录基线与实际值后再制定性能预算，不能随意保证固定 MB 数**。
- [ ] **连接/安全**：无设备、拒收、错误身份、重名、传输失败都明确可恢复；设备信任可撤销，发送到错误目标之前有清楚识别。
- [ ] **真实证据**：LocalSend 官方对照 ↔ 柠猫与柠猫 ↔ 柠猫完整传输、源/目标 SHA256、取消/断线/同名保护必须在真实 Windows 双端通过；无原生测试不得标 PASS。
- [ ] **回滚**：不修改/删除任何私人文件，离线索引与网络任务兼容已有 schema；R3 正式合并、监听、配对及权限需审批。

## 7. Codex 执行次序

1. 查实时 GitHub 与 P2 门槛；先在**隔离实验**确定 LocalSend Rust Core 最小 feature 能否复用、是否比薄协议适配更轻量，给出两种方案的制品增量及维护代价。
2. 运行无网络 loopback 及恶意文件名/取消/哈希/重名模拟，输出证据而不是只给框架图。
3. 在不影响 P2 功能的独立 P3 PR 中开发最小发送选择弹层、L2 唯一设备/任务管理、受限 Rust 传输接口，不为未来功能提前铺按钮/配置。
4. 用户专项批准后，完成官方 LocalSend ↔ 柠猫以及柠猫 ↔ 柠猫的两端真机互通，完善错误状态。
5. 除 R3 关卡和正式视觉合并外，局部 R0–R2 由 Codex 按现有批准的规范和 GitHub 规则自主测试、验收，**集中交付一次完整 P3-B 样机**。其余异地/同步待后续阶段，不阻挡 LAN 首发。
6. 以用户实际操作是否只需几步、安全可控、后台低占用为最终验收，而不是增加多少功能按钮和设置项。

> 本合同的「区域划分」为 P3 功能新增约束，不宣布 P2 尚待验收的所有视觉细节已最终定稿。发生冲突时先遵守安全与冻结决策，最终外观沿用根 `design.md` 与经用户验收的双眼球规范。
