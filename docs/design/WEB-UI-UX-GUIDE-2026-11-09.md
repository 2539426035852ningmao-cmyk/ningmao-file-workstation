# 柠猫 Web · UI/UX 开发实施指南
> 记录日期：2026-11-09
> 定位：项目设计系统的**实施附录**，不是第二套产品规范
> 最高优先级：根目录 `design.md` v0.2、D05、文件安全与网络授权合同

## 1. 设计目标与不可改变的原则

柠猫 Web 是 Windows 文件工作站的跨设备轻量网页入口，核心任务只有：**识别自己 → 找到设备 → 选文件 → 请求发送 → 对方确认 → 校验并保存**。不做传统网盘、文件资产总后台、AI 聊天平台或视觉展示站。以文件和接收对象为主角，减少仪表盘装饰、大型营销 Hero、常驻侧栏、动画画布和多重操作工具条。

适用的专业前端规范：
- 优先复用成熟且**许可清晰、源码可控**的组件；先盘点项目已有代码和版本，不引入功能重叠的组件平台。
- 统一语义 Token、字体、间距、嵌套圆角、线性 Lucide 图标和运动曲线；浅白、深蓝、亮蓝为**三个完整主题**，不允许混色主题形态。
- 先保证内容可读、主次分明、触点清晰、操作响应及时；微交互是功能反馈，不是默认炫技。
- 操作必须具备加载/等待授权/断线/重连/错误/取消/拒收/接收后校验/保存的准确状态。
- 支持桌面及移动端、浏览器键盘与触控、焦点、屏幕阅读器、响应式布局、`prefers-reduced-motion`。
- 做好打包体积、主线程开销和文件传输内存限制；传输性能不能因视觉效果退化。

## 2. 视觉参考库与实际采用结论

> 来源与用途记录为设计借鉴，不代表用户购买 Pro、允许复制付费源码、或已完成第三方源码许可证审计。外部网页列表和价格/使用限制会变化，采用前再次核验当时的原始许可与具体组件。

| 参考 | 官方入口 | 柠猫仅学习的部分 | 现在的取舍 |
|---|---|---|---|
| **BoardUI** | https://www.boardui.com/ / https://github.com/BoardUI/boardui | 克制的留白、语义 Token、信息层次、原生可访问组件 | 参考体系；避免整体移植大看板；Pro 组件需另有合法授权 |
| **Bencho** | https://bencho.dev/ | Toast、进度、选择、鼠标/键盘状态等可感知微交互 | 优先手写极少量 CSS 状态，未确认可复制许可前不移植源码 |
| **HeroUI Pro** | https://heroui.pro/about / https://docs.heroui.pro/ | 高成熟度产品后台的完整交互与可访问状态 | 仅借鉴；Pro 是商业授权，不采购不导入 |
| **beUI Pro** | https://pro.beui.dev/zh | 整站的对齐、品牌感、组件组合与节奏 | 只参考布局；不复制付费模板/动画块 |
| **Libraries.dev** | https://libraries.dev/ | 动画状态表达、细节收敛；免费 MIT 效果和 Pro 内容区分 | 当前文件传输工作台不需要 Thinking Orb、液态或边框光束，默认不安装 |
| **Watermelon UI** | https://ui.watermelon.sh/ | 响应式区块、可操作的组件演示、微交互示例 | 参考布局；具体复制前逐项检查源码/许可证，不整体下载组件库 |

设计语言优先顺序：**柠猫自身 D05 原则与主题 > 本项目已有组件与真实用户路径 > 参考 UI 行为 > 外部库的特效或模板**。

## 3. 现有技术栈和依赖门禁

W0 当前已具备：React 19 + Vite + TypeScript、Lucide React、CSS 语义变量、Vitest、Cloudflare Worker / Durable Objects、WebRTC。**维持小项目，不开展无证据的大规模重构。**

| 候选技术 | 什么时候需要 | W0 决策 |
|---|---|---|
| shadcn/ui + Radix | 复杂菜单/Dialog/Select/焦点流程，复用且无风格冲突 | 首选增量引入；原生 dialog 足够时无需安装 |
| Tailwind CSS | 多页面、大量可复用 utility 比当前 CSS 成本更低时 | 桌面已有；Web 当前局部 CSS，暂不为迁移而迁移 |
| Lucide React | 基础图标 | 已使用，继续唯一图标主源 |
| Motion | 真实复杂可中断布局/物理动画被用户验收确需时 | 目前 CSS 动画足够，不加依赖 |
| Magic UI / Aceternity UI | 少数确有产品价值且许可允许的视觉模块 | 当前不安装、不放宣传特效 |
| react-resizable-panels | 双栏真实可拖分隔并要求尺寸持久化 | 首版无此交互，不安装 |
| dnd-kit | 页面内排序/跨区拖动，不是浏览器拖入文件 | 首版仅 HTML File DnD，不安装 |
| Zustand | 状态真实跨多个复杂模块共享且现有 hooks 难维护时 | 暂不安装 |
| TanStack Query | 多端点查询缓存、失效/变更协调成为实际痛点时 | 当前 API/me 简单，不安装 |
| Recharts | 有真实持续的统计图表业务需求时 | 文件互传首版不应有图表，不安装 |

新增包需先回答：功能需求、当前替代方案为什么不足、许可与复制限制、打包增量、可访问性/性能表现、是否能单独回滚、CI 是否通过。禁止为了“最新最好”叠加完整 UI 框架。

## 4. 视觉与交互基线

- **形态**：桌面横向内容区仅 2 个主工作卡片（设备/发送），接收与记录在次级区域。手机单列，动作不得离开当前操作上下文。首页不需要超过操作区域的大型 Hero 或无任务意义的图表。
- **Token**：4/8/12/16/24/32px 间距；面板圆角约 16–18px，内层 10–12px，控件 8–10px；不堆叠描边与阴影。图标 16–20px，必要的空状态较大图标不超过 28px。
- **主题**：浅白偏中性白灰；深蓝使用深蓝黑分层；亮蓝**整套页面与容器均处于亮蓝主题色家族**，而非只改按钮。所有主题的正文/辅助字、边框、焦点和危险状态分别审核。
- **字体**：系统字体优先，不下载远程字体；主体 12–14px；重要标题 16–20px；文件列表始终优先名称，完整名称通过 title/详细信息可看。
- **动画**：120–180ms 高阻尼感的短反馈，禁止无限循环显卡效果；悬停、按下和进度明确响应；reduced-motion 下保留状态语义不播放动画。
- **无障碍**：Tab、Enter、Esc、Modal 焦点捕获/退出回焦点、触摸点击区域（移动端关键主控件目标 44px）、提示不只靠颜色，文本对比度目标 4.5:1。
- **真实状态**：连接未成功不得显示在线；文件尚未完成接收/校验不得显示成功；校验完成但未保存只能写“已校验，可保存”；断线不得假装自动续传。

确认精确应用基线、当前分支/PR/CI，再改代码。不要改受保护 main 或自动合并 #77/#78；不覆盖其他工作区。

## 6. 验收计划

| 项目 | 检查手段 | 合格条件 |
|---|---|---|
| 视图响应 | 桌面 1440/1024、手机 390/320 CSS px | 不横向滚动，不遮挡关键操作，次级内容可滚动 |
| 完整主题 | 浅白/深蓝/亮蓝各自截图，至少页面+弹窗 | 同一色彩体系；文字/图标/状态有清晰层级 |
| 文件与设备状态 | 无设备/在线/离线/未选择/待确认/接收/拒绝/取消/失败 | 语义准确，不制造假数据、假进度 |
| 文件安全 | 合成 TXT/PNG；哈希一致、超过64MiB拦截 | 来源未移动，校验失败不可保存 |
| 键盘/可访问性 | Tab/Enter/Esc/焦点、dialog、屏幕阅读器标签 | 所有主要动作可达、弹层可退出、回焦点 |
| 低动效 | 系统 prefers-reduced-motion | 停止非必要变换，交互状态仍能理解 |
| 工程边界 | npm test/build/Worker dry-run、依赖 diff、license | 测试通过、包大小变化可解释、未引入不必要依赖 |
| 真实互传 | 同账号两个独立 OS/浏览器、跨网 | 需单独验收；未做时标 NOT_TESTED |

## 7. 回滚与更新

仅在 `apps/web` 的独立 Web 分支/PR 进行源代码改动；本文件只是文档，不授权修改第三方组件、采购 Pro 服务或创建 Cloudflare 公网资源。UI 差异可单独回滚，不触及现有桌面功能、SQLite 或真实文件。正式主题值、跨端设计 token 同步与网络上线都要先完成对应验证。
