# 柠猫文件工作站 · 双眼灵动系统视觉与交互规范 V1.0

> 2026-10-25 · 用户已确认的设计决策 + 待实机验证的设计建议  
> **文档阶段：Design Spec / Pending UI Acceptance；不代表代码已实现、CI/原生测试已通过。**  
> 本文是根目录 [`design.md`](../../design.md) 的**候选增补**，不得覆盖其中的文件安全语义、43 项冻结产品决策、P0/P1 与 P2 的验收限制。最终验收后将结论归并回唯一规范源 `design.md`；在此之前若有冲突，以既有安全约束为准。

## 0. 设计北极星

**完整圆球只有两只小眼睛。没有猫、猫耳、嘴、眉、腮红、脚、手、金属按钮、环形辉光。** 这是桌面文件工具，不是桌宠。

三层身份：
1. **L0 完整双眼球**：入口主体，注视与眨眼产生一点生命感。
2. **L0.1 胶囊**：第一次点击圆球，横向柔和延展，保留左端双眼，展示当前架名称与少量状态。
3. **L0.5 轻预览 / L1 完整架**：第二次点击胶囊进入轻预览；用户明确选择「打开文件架」进入完整窗。双眼**从完整球中抽象为左上角 2 个小眼睛**，与标题同组，成为非交互动态品牌标识。

L2 管理中心为独立按需窗口，延用设计 Token，不占 L1 的紧凑窗口空间。保留快速直达完整架的操作路径，不强迫熟练用户经过三次点击。

**确定的选择**：球体配色独立于应用深/浅主题；完整窗口右上角有专用「收起」按钮，点击恢复到该架自身入口或 Dock 节点；左上角的双眼**不能当按钮**。

## 1. 三款独立球体配色（用户明确确认）

| 皮肤 ID | 中文名 | 建议基础色 | 眼睛前景 | 基本观感 |
|---|---|---|---|---|
| `warm-white` | 暖白 | `#F5F3EF` | `#191B20` | 柔和、平面、干净 |
| `navy-black` | 深蓝黑 | `#191E28` | `#F5F6F8` | **接近黑色，蓝色含量很少，高冷、哑光、近乎纯平** |
| `brand-blue` | 主题蓝 | `#2869D6` | `#F8FAFF` | 现有品牌蓝，清亮但克制 |

- 这只是候选设计 Token，最终校色须结合实机屏幕验收。
- 三种都是**纯净圆球与同一套眼睛轮廓**，不因为皮肤改变交互逻辑或动画时间。
- 皮肤手动选择并持久化，**不跟随应用的深浅主题自动切换**。应用仍保留已有深/浅主题独立开关。
- 重点禁令：**深蓝黑不得有外轮廓描边、常驻蓝色发光环、镜面高光、鼓起来的光泽、浮夸玻璃塑料渐变**。靠轮廓、眼睛和有限的位移动效表达个性；只有必要的投放/键盘焦点反馈可以用独立 UI 状态清晰表达。
- 轻预览与文件架依照应用主题选择易读的容器表面；**不得把整张文件架染成皮肤颜色**。只保留眼睛的品牌血统，眼睛本身以窗口背景对比色呈现。

## 2. 形象几何与尺寸（待精修值）

- L0 推荐 48×48 Windows 逻辑 CSS px；默认纯圆；透明背景原生悬浮窗口的点击/投放热区需独立验收。
- 球体两只眼睛：左眼略长、略宽，右眼略短、略细；整体位于圆球的中部偏右上；均为简洁略倾斜的黑/白实色轮廓。
- 初版用**独立创作的 SVG 曲线/椭圆**，而非复制参考项目的眼睛路径、点阵/几何表、复刻文件或资源。
- 眼睛支持成组视线偏移、眨眼开合和小幅倾斜；不能从正圆外逸出、不能产生三只眼或眼睛错位。
- 胶囊建议高 48px、宽约 160–200px，按名称/状态截断，不随文字无限变宽；左端双眼随主体自然保留，**不叠加第二颗圆形球底座或描边外环**。
- L0.5 轻预览暂定约 300×224px（可随桌面可用空间、安全文案及文件数量微调）。L1 继续以 **420×520 默认 / 340×320 最小**作为已选窗口建议值；必要时扩窗。绝不把研究原型的大工作台当常态。
- 预览/完整窗左上角双眼可视区域暂定约 22×20px，布局占位约 28×28px，距左边 12px，标题间隔约 8–10px；尺寸经 125%/150% DPI 与中文文本缩放确认。
- 左上双眼不是可点击控件：没有 hover 按钮底色、手型鼠标、焦点占位、`button` 语义或隐藏操作。可作为 `aria-hidden` 装饰；标题/窗口操作另提供可读名称。

## 3. 视觉层级与完整文件架

顶栏使用 **一个 44–48px 操作带**：左侧「双眼 + 当前文件架名称/切换」，右侧**专用收起按钮**及搜索、添加、更多操作。功能按钮排列可在高保真中微调，但不增加第二层常驻工具栏。

- 收起按钮建议 32–36px 命中区域，独立图标与明确 tooltip/`aria-label=收起到悬浮入口`。
- 完整窗默认没有永久左导航、默认详情、独立统计底栏与巨型品牌 Logo；文件网格是主内容。
- 文件名单行省略，系统内容区间距沿用 `design.md` 已选 4px 节奏、20/16/12/8px 圆角系统。
- 浅色/深色 UI 的缩略图、文字必须清晰；不把模糊玻璃叠到图片或大面积文字上。
- 轻预览：顶栏双眼+架名+数量，最近最多三个文件缩略图（无文件显示简短空状态），底部左侧 **「仅保存引用」**或 **「复制到目录 · 保留来源」**，右侧明确「打开文件架」。
- L1 完整窗安全说明一眼可识别：临时引用只保留引用、绑定架安全 Copy 到真实目录。用户必须能区分，不依赖颜色、动画或眼睛表情。
- 双眼图形延续身份，但**不能让正在眨眼的标识造成标题区布局跳动**。

## 4. 动效语言（设计预设，非实测承诺）

| 场景 | 推荐行为 | 试验范围 |
|---|---|---|
| 待机 | 低频、非规律眨眼，偶尔极轻微注视，无常驻大幅呼吸 | 间隔不机械固定 |
| 鼠标靠近 | 眼睛平滑注视，不自动连续打开两层窗口 | 约 100–160ms |
| 首次点击 | 小幅 Squash 后主体横向延展，眼睛稳定到左端 | 约 200–250ms |
| 胶囊再次点击 | 容器展开轻预览，先容器后内容淡入 | 约 210–280ms |
| 预览→完整架 | 小眼睛对齐到标题位置；新原生窗口可用协调过渡，不要求跨窗逐帧变形 | 按实机测定 |
| 文件拖入 | 立即高亮**当前冻结投放目标**，显示具体引用/复制语义 | 不得延迟命中 |
| 完整窗收起 | 内容先淡出，向该架自身球/ Dock 节点方向收敛，最后恢复相应入口 | 约 200–280ms |
| 成功/失败 | 一次克制微动作 + 文本状态；失败不可仅靠表情 | 约 120–180ms |

**运动原则**：身体形变、眼睛姿态与窗口生命周期是三个独立系统；状态可以中断，遵循「原生投放/安全 > 错误/任务 > 窗口 > 点击 > 待机」的优先级。隐藏状态停止无意义帧循环；`prefers-reduced-motion` 关掉非必要形变和眼球追踪，保留可用的静态功能。

避免眼睛随机眨动影响文件区阅读；完整窗口里的眼睛比入口里的更安静。

## 5. 智能混合 Dock / 多文件架（用户明确确认）

- 左右贴边：**竖向 Dock**。上下贴边：**横向 Dock**。自由悬浮：紧凑排布并保留用户手动指定的模式/位置。
- 1 个文件架保持一个安静圆球；2–5 个架展示易识别的节点；6+ 架按常用/更多菜单折叠（推荐，需验收后定上限），不在屏幕上摆一整列持续眨眼的球体。
- **默认活跃的主入口**可以展示完整动态双眼；其他节点以静态简约标记区分，不让十几颗眼睛一起动画。每个架都保持独立身份、引用记录、标签、视图、位置与来源类型。
- 用户可拆出独立文件架和恢复 Dock；不得静默合并/重排已手工布局的文件架；多个显示器按各自工作区恢复，不越过任务栏。
- 在 Dock 拖入多个文件时显示**单一明确当前目标**，冻结目标身份、窗口与放置语义直到 drop/cancel/leave；不可让布局动画抢夺原生拖放目标。
- 屏幕边缘临时唤出时，确保有效命中区域与可见区域一致且不会意外吞掉其他软件的事件。

## 6. 窗口收起（用户最后确认）

右上角**独立收起按钮**，不是左上双眼，不只是更多菜单。

收起必须返回该架**对应的独立入口 / Dock 节点**；不能误收回其他架，也不等于退出程序或删除记录。窗口状态与位置恢复遵循原有 P2 约束；跨屏时根据目标屏幕/可见工作区选择安全过渡，不画错误的跨屏飞越动画。原生拖放、高风险任务执行中必须阻止可能破坏操作的收起，并给出可读原因。

- 允许参考公开的**通用原理**：SVG、插值、弹簧动力学、状态机、RAF 节能、键盘/焦点/指针事件。独立设计视觉参数及代码，使用仓库已批准的依赖和许可路径；任何新依赖先核查许可证。
- 尊重 Tauri2 / React / Rust / SQLite 原有安全边界；不得为透明悬浮入口新增宽泛的前端磁盘访问权限。不能只模拟 HTML DnD 取代 Windows 原生文件拖放。
- 不能因为「我们也开源」就推定有再分发权；可参考 ≠ 可复制素材、代码或商标。

## 8. 已确认 vs 待验收

**用户已确认：** 双眼无猫形象、三球色独立选择、深蓝黑哑光无描边/鼓光、圆→胶囊→轻预览→完整架、窗口左上角只保留双眼作为非交互标识、右上角专用收起、智能混合 Dock 与多架独立性。
