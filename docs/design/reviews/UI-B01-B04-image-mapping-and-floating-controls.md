## 1. UI-B01 · 去外围可见矩形容器/黑框

用户反馈：现有圆球、胶囊、轻预览附近有独立于主体之外的可见矩形/圆角透明外壳，尤其胶囊周围黑框显得笨重、干扰桌面感和拖动手感。目标：主体作为独立圆球、胶囊、轻预览浮层直接立于桌面上，**不要永久可见的第二层边框/大黑框**。

须区分：
- **可视外壳**：希望删除或隐藏永久绘制的外围矩形、边线、附带投影/背景；容器外部不得呈现宽大的黑色衬底。
- **原生窗口命中矩形**：Tauri/Windows 可能仍存在用于投放/指针的 OS window rect，不能简单移除真实必要命中区。研究透明像素区域是否实际拦截桌面操作及同屏拖拽窗口；必要时采用窗口几何缩紧、穿透和透明区域事件策略，但绝不能破坏目标冻结、Drop/Copy 安全及其他应用鼠标操作。
- **完整文件架**：其原生标题栏/阴影和重边缘也需检查，但不擅自决定去掉所有可拖拽边界，必须保持移动、缩放、焦点、跨屏正常。
- 不把截图红色标注矩形误认为软件本身绘制的黑框。定位“实际可见线”和“编辑标注线”，按实机/原 DOM、窗口渲染逐一核对。

状态：**问题与无壳方向已确认，具体窗口技术方案待调查、演示和验收**。

## 2. UI-B02 · 眼球轻度鼠标视觉跟随

用户明确要求：图1所在圆球入口的眼睛可以识别鼠标方向，做**轻微、缓动、克制**的注视跟随；其他带左上小眼睛的窗口仅轻度内部跟随，仍是非交互品牌标识，不把眼睛当操作按钮。

状态：**目标已确认；当前功能质量和敏感范围待实机检查**。

## 4. UI-B04 · 胶囊右上方的“挤出式”渐进关闭小球

**当前（图3）：**胶囊右上方有直接可见的深色圆形 X，且有明显外围矩形容器。

**用户手绘期望（图2）：**
1. 常态保持干净长胶囊。
2. 鼠标靠近胶囊右上边缘、略向上移，胶囊局部有“被挤出一个小圆球”的连续形变；此时球不是红色。
3. 继续向上深入可触发区域，小球逐渐成为红色关闭按钮，有过渡层而非突然满红。
4. 点击后执行**已确认的「收回圆球」动作**：胶囊自然缩回对应双眼圆球，保留原文件架身份与内容，不删除、不退出、不隐藏为无入口。

明确区别：用户表达的是**从胶囊本体生长出来的连续外形**，不是在固定透明大框里突然显示一个另外的红色 X 圆按钮。

还待定义的设计工程问题：
- 外形连接过渡是否保留小的圆弧桥/颈部？
- “靠近”、“稍上移”、“再向上移”的真实指针轨迹/距离、允许斜向进入的可用性与触摸/键盘等价操作。
- 取消 hover 时的逆向动效、快速进出/拖放并发处理。
- **已确认按钮动作：收回对应的双眼圆球（A）。** 仍待设计确认的只是手势阈值、动画曲线、误触保护与缩回过程的可视连接。
- 若关闭区真的在胶囊上方：扩展原生透明窗口区域应只拦截自身交互，不制造用户刚要求去掉的“隐形大片拖拽拦截框”；严格测试可视/命中区域。

状态：**点击语义已冻结为「收回圆球」；指针触发、挤出轮廓及动效仍为待讨论设计，暂不实施**。

## 8. 补充确认：轻预览返回与关闭是不同层级

用户在明确四图关系（本轮**图1为手绘目标轻预览、图4为当前轻预览**）后，确认两按钮语义：

| 轻预览右上动作 | 已确认目标状态 | 说明 |
|---|---|---|
| 左箭头「返回」 | `quick-peek -> capsule` | 退回**当前文件架对应**的胶囊，而不是关闭文件架 |
| 关闭符号「收回圆球」 | `quick-peek -> orb` | **跳过胶囊阶段**，直接回到当前文件架对应的双眼圆球；记录、绑定/引用、窗口归属、排序等保持不变 |

- 两者**不可以实现成同一命令**或不论点哪个都回胶囊。
- 胶囊自身右上挤出的小球点击，同样 `capsule -> orb`（见第7节）。
- 返回与关闭在图1中是用户绘制的美术目标：默认尽量仅显示箭头/关闭符号，悬停逐层显现选中圆缘；返回采用主题蓝，关闭采用中性预热→红色内层激活。具体形态、颜色阈值及点击热区仍待继续讨论。
- 这两项语义已经由用户分别确认，不需重复发问；**本次只更新设计记录，不改 PR #35 功能代码，不自动合并，不宣称验收通过**。

## 9. 新确认：胶囊关闭小球采用 A「连体生长」

用户在比较 **A 连体生长** 与 **B 挤出后轻微分离** 两款示意后，明确选择 **A**。这是用户的最终方向选择，不应再以 B 代替。

- **形态几何：** 小球从胶囊右上角边缘连续、圆润地“挤出”，在整个预热、激活、取消与收回过程中，始终与胶囊本体保持视觉连接；不是独立弹出的圆形按钮，也不在中途断开。
- **美术目标：** 延续暖白 / 哑光深蓝黑 / 品牌蓝的胶囊主体材质；不出现外围可见矩形框、大黑色壳、额外发光描边或镜面鼓光。
- **交互状态：** ①常态干净胶囊 → ②靠近右上端，形成与胶囊相连的中性小鼓包 → ③进一步上移，连接的小圆端内部逐渐呈现红色关闭态 → ④点击「收回圆球」执行 `capsule -> orb`；离开则连续逆向回归常态。
- **红色限制：** 红色是局部内层关闭反馈，不允许预热态直接出现大红色，也不得使胶囊整体染红；具体激活阈值、轮廓连接颈部和过渡时间仍待详细讨论。
- **已冻结语义：** 点击小球只使此胶囊变回对应双眼圆球，文件架和引用/文件不被删改；轻预览左箭头回胶囊、X 直接回圆球，此项与图1/图4分层关系保持一致。
- **原生技术注意：** 不可为了显示越界鼓包而引入大型可见/不可见外围窗口截获区；需要设计安全且可预测的命中区域，并在 Tauri/Windows 原生拖入期间遵守目标/矩形冻结规则。键盘与 reduced-motion 必须仍能找到等价的「收回圆球」操作。

**状态：连体形变方向已确认。** 鼠标靠近触发带、深悬停红色激活阈值、弱化动效/键盘替代方式仍待继续逐项讨论；目前仅设计决策记录，不修改 PR #35 软件代码，不代表功能已实现或通过 Windows 验收。

## 10. 新确认：胶囊挤出式关闭选择 A「连续跟随式」

用户在 A「连续跟随式」、B「两段触发」、C「悬停延迟触发」之间，明确选择 **A**：**鼠标越靠近胶囊右上角、越向上移动，胶囊右上角的连体小球越明显地挤出；进入更深入的核心交互区域后，才逐渐变红。**

### 已确认的运动语言

1. **待机**：长条胶囊纯净、无外壳、无常驻圆形关闭按钮；不得默认出现红色。
2. **连续预热**：鼠标从正常区域向右上角靠近，形变进度随位置连续变化，连体小球从胶囊轮廓柔和生长，不突然出现完整独立球。
3. **继续向上**：小球在连接不断裂的前提下更明显地凸起；可以用小幅缓动平滑追随鼠标位置，避免机械逐像素抖动。
4. **核心激活**：进入足够深入的关闭触发区后，**局部内部**渐变为红色并明确显示 X；胶囊其余主体不变红，不能把危险外观套到整个背景。
5. **点击**：只执行先前确认的「收回圆球」`capsule -> orb`，保留架 ID、内容和布局；点击不执行删除、退出、解绑或其他文件操作。
6. **退出/取消**：鼠标撤离时按照当前进度顺畅逆向缩回，不留红点/鬼影；快速往返、按 Esc、文件原生拖入时遵守交互优先级，避免误收回窗口。
7. **一致性**：对三球色及深浅 UI 共用同一形变逻辑；深蓝黑坚持平面哑光、无外描边、无鼓起高光。眼睛自身不被挤出小球挤压或错位。

### 需要 Codex 在实施前特别核实的技术约束

**本轮只冻结设计，不批准实施。** Tauri/Windows 顶层入口的真实外形绘制区域、透明窗口与 OS 命中矩形不一定一致。不能为了实现“越往上越明显”再引入用户正在投诉的可见大黑框或覆盖桌面的不可见大矩形。

- 视觉进度应依托单一稳定的胶囊基准和明确的右上角感应带；具体大小、触发阈值、位移曲线**尚未由用户批准**，不能写死为最终规范。
- 挤出轮廓始终相连（第9节已冻结）；**“连续跟随”现明确指生长程度连续响应指针运动**，小球中心点是否也要跟随水平位置尚需另行确认，暂不推定。
- 原生 `DragSession` 正在接收文件时优先锁定 Drop 目标、实际窗几何及安全语义；不得让挤出导致接收区域漂移/误触。
- 动效组件不可占用整个桌面的指针事件；无障碍键盘入口、`prefers-reduced-motion`、高 DPI、贴边方向和屏幕工作区须保留；红色激活不可成为唯一可识别操作线索。

**状态：用户选定 A「连续跟随式」，已同步设计分支；不代表代码或 Windows 原生功能已实现/验收。**

## 11. 新确认：关闭小球固定生长在胶囊右上角（A）

用户已明确在「A 固定右上角」和「B 小范围左右跟随」之间选择 **A**。此项是已确认设计决定，不能在实施中重新解释为小球随鼠标水平游走。

**已确定：**
- 关闭小球的**生长锚点固定在胶囊右上角**。从胶囊同一个位置持续连体挤出，无分离、漂浮、横向迁移。
- 指针位置仅驱动 **生长量/凸起程度**（以及此前确认的深入核心时红色内层激活程度），不是驱动小球中心在 X 轴跟随。
- 回退时沿同一路径逆向收回，底层胶囊长度、文件架标题与眼睛位置稳定，不随挤出动画来回偏移。
- 胶囊主体的皮肤与深/浅主题选择仍按原规范；哑光深蓝黑不引入外描边或镜面光。

## 12. 新确认：关闭球必须红色核心激活，核心区选择 B「中等面积」

- `idle`：胶囊无凸起；没有独立常驻关闭按钮或可见大黑框。
- `protruding-neutral`：固定右上锚点**连体**、**连续随鼠标接近与上移而生长**；未变红，点击不关闭；普通点击与原有胶囊展开行为须避免冲突（不得因禁用关闭而误触其他动作）。

- `retracting`：未点击而移出核心区域，先撤销红色，再随指针退离柔和逆向收回；点击成功则与胶囊同步连续收回对应双眼圆球。

**实现约束**：红色视觉确认与实际可点击性必须一致。鼠标离开红区时，不能残留仍能触发的“透明关闭命中区”；用同一个状态/阈值决定红色激活与关闭指令允许。不要仅靠颜色传达，激活时同步体现 X 与清楚的指针/焦点反馈。

**具体尺寸尚未冻结**：中等面积不等于某一固定像素半径；要在不同缩放比例和 DPI 的真实 Windows 桌面上校正命中区，避免触发颤动，并提供键盘及 reduced-motion 等价可用路径。原生文件拖放时严格遵守冻结几何、冻结目标与阻止窗口收缩的安全规则。

## 14. 新确认：外围黑框移除后，本体保留极轻微柔和阴影（A）

### 已冻结的视觉方向

1. 圆球、灵动胶囊和轻预览只显示它们**自身的真实几何形状**，不得将大的透明/黑色/灰色矩形窗口画成可见衬底，不得绘制第二层外围框或持久在线轮廓。

**状态：外围可见矩形外壳移除 + 极轻微主体柔和阴影已确定；仅同步设计分支，PR #35 应用代码未变更、原生验证尚未完成。**

## 15. 新确认：圆球与胶囊整个可见主体的非按钮区域都可拖动（A）

用户在「A 整个主体非按钮区域可拖动，轻点保留展开，超过阈值才启动拖动」与「B 胶囊仅从双眼/指定把手可拖动」之间明确选择 **A**。

### 已确认交互合同

1. **圆球（orb）**：整个可见圆球主体可作为拖拽起点（不需要额外显示把手或外围可见框）。
2. **胶囊（capsule）**：整个胶囊**可见主体中的非按钮区域**可作为拖拽起点，不限制必须抓住双眼；右上连体关闭小球的红色有效关闭区、其他正式控件不得被通用拖动事件覆盖。
3. **单击和拖动区分**：按下到抬起的位移未超过交互阈值时，走该形态已有的轻点展开动作；位移越过阈值才进入拖动（不应把轻微手抖当拖动），一次指针序列只允许触发**一个**结果。具体阈值像素要基于 Windows DPI/触控板实测，暂不硬编码为用户已定数字。
4. **拖动手感**：要从实际指针按下位置抓住主体、移动过程保持指针与主体的相对位置，避免跳到中心、闪烁、瞬移和窗口黑框拖拽；抬起后自然停留，落点不能跳回旧位置。
5. **点击安全**：成功判定为拖动后，`pointerup` 不再冒泡/模拟成展开点击或「收回圆球」；点击关闭小球需满足已确认的中等面积红色核心激活。眼球跟随视觉不能抢占 pointer 或阻挡拖动。
6. **桌面体验**：删除视觉外围矩形壳后，仍确保拖动手势命中的是**可见主体而非透明大矩形**；主体之外桌面正常点击/拖动、其他应用不应被遮挡。主体边缘允许极轻柔和阴影，但阴影不可成为假手柄/额外点选区。
7. **原生文件拖放并发**：将“用户拖动窗口”和“用户从 Explorer/创作软件向文件架拖入文件”区分。原生 DragSession 正在接收时维持源文件安全、目标 ID 与命中几何冻结，不能因为通用主体拖动而更改 Drop 目标或发生误收回。
8. **跨状态连续性**：拖动前后仍保留对应 orb / capsule 形态、文件架身份、窗口/屏幕记忆，原有 Dock 自动归位机制不可被未经确认的强制吸边改写。
9. **键鼠与性能**：鼠标、触控板、高 DPI、多显示器可回归；变形和眼球跟随频率需轻量，减少动画偏好继续生效。

3. **离开顶部吸附**：恢复**右上角**固定连体生长。顶部自由拖离后不应在拖动中闪烁反复换角；具体换角时点以清晰稳定的吸附状态为准，需在样机验证。
4. **不变约束**：横向胶囊、眼睛正立、名称水平、圆球/胶囊非按钮主体可拖动、边缘主体完整可见、微小边距、极轻柔和轮廓阴影、无可见黑框。

6. **自动映射感应方向**：右下角时，鼠标深入核心应通过**右下方向**自然触发，不可沿用向上的激活路径使按钮无法使用。
7. **优先级声明**：本条是对第11节与第18节中“固定右上角”简写的**明确例外和修订**，也将第19节的“待用户确认切换条件”**关闭为已确认**。如果历史文档提到“只在空间不足时换右下”，以**本条 A 自动换角**为准。
8. **工程安全**：需要让右下凸起完整可见并可被点击，且不得扩展成多余透明大矩形吞桌面点击；不破坏原生文件拖放时冻结目标/窗口命中矩形，保持各 DPI/多屏幕的有效工作区安全。

**尚待设计/样机验证**：外圈实际感应距离、最大眼睛偏移量、平滑速度，以及移动窗口的拖动过程中是否跟随鼠标。不要把工程试验参数视为用户已批准的精确数字。
