## 1. UI-B01 · 去外围可见矩形容器/黑框

用户反馈：现有圆球、胶囊、轻预览附近有独立于主体之外的可见矩形/圆角透明外壳，尤其胶囊周围黑框显得笨重、干扰桌面感和拖动手感。目标：主体作为独立圆球、胶囊、轻预览浮层直接立于桌面上，**不要永久可见的第二层边框/大黑框**。

须区分：
- **可视外壳**：希望删除或隐藏永久绘制的外围矩形、边线、附带投影/背景；容器外部不得呈现宽大的黑色衬底。
- **原生窗口命中矩形**：Tauri/Windows 可能仍存在用于投放/指针的 OS window rect，不能简单移除真实必要命中区。研究透明像素区域是否实际拦截桌面操作及同屏拖拽窗口；必要时采用窗口几何缩紧、穿透和透明区域事件策略，但绝不能破坏目标冻结、Drop/Copy 安全及其他应用鼠标操作。
- **完整文件架**：其原生标题栏/阴影和重边缘也需检查，但不擅自决定去掉所有可拖拽边界，必须保持移动、缩放、焦点、跨屏正常。
- 不把截图红色标注矩形误认为软件本身绘制的黑框。定位“实际可见线”和“编辑标注线”，按实机/原 DOM、窗口渲染逐一核对。

状态：**问题与无壳方向已确认，具体窗口技术方案待调查、演示和验收**。

## 2. UI-B02 · 眼球轻度鼠标视觉跟随

用户明确要求：图1所在圆球入口的眼睛可以识别鼠标方向，做**轻微、缓动、克制**的注视跟随；其他带左上小眼睛的窗口仅轻度内部跟随，仍是非交互品牌标识，不把眼睛当操作按钮。

现有 `apps/desktop/src/orb/OrbMotionController.ts` 已有部分 pointermove / easing / blink 逻辑。下一步不是假设没有实现，而是核实真实 Windows 当前鼠标经过/靠近时动画是否起效、是否被外框/overlaid layer 阻断、眼球视觉是否足够、容器能否正确定位。可研究参考项目通用原理，但不能直接取受限代码/资产。

状态：**目标已确认；当前功能质量和敏感范围待实机检查**。

## 3. UI-B03 · 轻预览右上角返回和关闭按键

**当前（图4）：**返回箭头显示在浅灰圆角方块状背景中；旁边关闭是独立 X，风格与目标不一致。

**用户手绘期望（图1）：**
- 默认只看到返回符号和关闭符号；不常驻明显的圆形外边框。
- 鼠标接近/悬停时外缘与选中反馈逐层出现，而不是两个始终高亮的圆贴片。
- 返回按钮关联柠猫品牌蓝的填充式状态，需明确默认/浅 hover/聚焦的差别。
- 关闭按钮不是默认红；红色需要集中在小的内层区，可能有中间过渡边缘；深入操作区后才进入明显红色关闭状态。
- 还需讨论具体 close/back 行为和手势触发位置，不能臆造“关闭等于删架/退出程序”等语义。

状态：**绘制目标方向明确；精确状态、色彩、可访问性和关闭行为未冻结**。

## 4. UI-B04 · 胶囊右上方的“挤出式”渐进关闭小球

**当前（图3）：**胶囊右上方有直接可见的深色圆形 X，且有明显外围矩形容器。

**用户手绘期望（图2）：**
1. 常态保持干净长胶囊。
2. 鼠标靠近胶囊右上边缘、略向上移，胶囊局部有“被挤出一个小圆球”的连续形变；此时球不是红色。
3. 继续向上深入可触发区域，小球逐渐成为红色关闭按钮，有过渡层而非突然满红。
4. 点击后执行**已确认的「收回圆球」动作**：胶囊自然缩回对应双眼圆球，保留原文件架身份与内容，不删除、不退出、不隐藏为无入口。

明确区别：用户表达的是**从胶囊本体生长出来的连续外形**，不是在固定透明大框里突然显示一个另外的红色 X 圆按钮。

还待定义的设计工程问题：
- 外形连接过渡是否保留小的圆弧桥/颈部？
- “靠近”、“稍上移”、“再向上移”的真实指针轨迹/距离、允许斜向进入的可用性与触摸/键盘等价操作。
- 取消 hover 时的逆向动效、快速进出/拖放并发处理。
- **已确认按钮动作：收回对应的双眼圆球（A）。** 仍待设计确认的只是手势阈值、动画曲线、误触保护与缩回过程的可视连接。
- 若关闭区真的在胶囊上方：扩展原生透明窗口区域应只拦截自身交互，不制造用户刚要求去掉的“隐形大片拖拽拦截框”；严格测试可视/命中区域。

状态：**点击语义已冻结为「收回圆球」；指针触发、挤出轮廓及动效仍为待讨论设计，暂不实施**。

## 7. 补充确认：胶囊小球点击语义（用户选择 A）

用户在四图对应关系澄清后，明确回答 **A**：胶囊右上角经“挤出→中性预热→深入悬停红色激活”的小圆球，被点击时 **「收回圆球」**。
