## 2. 已确认产品目标

- 日常文件架为主要工作空间，管理中心按需进入。
- 管理中心保留独立原生窗口，一级栏目为文件与素材、任务中心、设置。
- 三形态为悬浮球、横向展开、大展开；中展开/轻预览取消。
- 启动模式只有悬浮球（默认）或直接大展开。
- 三套完整主题为白色、深蓝色、亮蓝色，跨所有窗口一致。
- 禁止窗口套窗口；每个工作窗口同一时刻只允许一个主要辅助面板。
- 文件引用、真实复制、回收、互传和 AI 安全语义继续遵守既有决策。

## 3. 当前候选代码事实

### 3.1 悬浮球、胶囊和旧轻预览

- Tauri Entry 状态枚举当前仍是 Orb、Capsule、QuickPeek；几何尺寸分别为 48×48、184×48、300×224。证据：apps/desktop/src-tauri/src/entry.rs，L7–12、L149–153。
- DesktopEntry 前端组件根据状态渲染 Orb 或 QuickPeek；Capsule 目前只显示文件架名称、语义状态和箭头。证据：apps/desktop/src/orb/AdaptiveShelfDock.tsx，L49–59。
- QuickPeek 当前包含最近素材、文件架列表搜索、外观设置、返回/收起和打开文件架入口。证据：apps/desktop/src/orb/QuickPeek.tsx，L12–16。
- 目前 Capsule 还不是用户要求的增强型快捷工作层；QuickPeek 的少量有价值能力需要重新分配，不能直接删组件后丢失入口。
- OrbMotionController 当前主要处理双眼视线、眨眼和窗口移动状态，不是完整的窗口形变控制器。证据：apps/desktop/src/orb/OrbMotionController.ts，L1–23。

### 3.2 为什么大展开会有跳跃风险

- Orb/Capsule/QuickPeek 属于 desktop-entry WebView 内的前端状态；其容器尺寸由 Rust 的 entry_geometry 调整。证据：apps/desktop/src-tauri/src/desktop_runtime.rs，L246–322、L324–385。
- 当前 CSS 对 Orb→Capsule 使用 220ms 的 clip-path 动画，对 QuickPeek 使用 240ms 容器动画和延迟内容动画；没有看到与 Full Shelf 几何一致的第三段连续动画。证据：apps/desktop/src/style.css，L284–341。
- 点击打开完整文件架会调用 desktopOpen；Rust open() 通过 shelf_windows::ensure 获取 main 或独立 shelf 窗口，再定位、显示和聚焦。证据：apps/desktop/src/orb/AdaptiveShelfDock.tsx，L26–27、L48–56；apps/desktop/src-tauri/src/desktop_runtime.rs，L423–490。
- 独立文件架窗口在需要时由 WebviewWindowBuilder 新建，使用 420×520 初始尺寸。证据：apps/desktop/src-tauri/src/shelf_windows.rs，L55–103。
- 因此当前大展开路径存在原生窗口/前端形变交接：胶囊动画和大窗口显示不是同一段连续几何动画。这是大展开跳跃的明确高风险原因；最终根因仍需在精确 Windows 包上采集窗口位置、尺寸、显示和焦点时序。
- 管理中心则是独立 manager 原生窗口，已有单实例激活逻辑，初始 1040×720、最小 760×520。证据：apps/desktop/src-tauri/src/desktop_runtime.rs，L669–705。

### 3.3 拖放约束

- entry_geometry 在 native_dragging 时不移动、不缩放、不隐藏窗口；源码注释明确要求不要在 OLE Enter 与 Drop/Leave 之间改变目标窗口几何。证据：apps/desktop/src-tauri/src/desktop_runtime.rs，L246–255。
- present() 在切换入口形态前调用 require_idle；正在原生拖放时拒绝改变形态。证据：apps/desktop/src-tauri/src/desktop_runtime.rs，L324–353；require_idle 位于同文件 L145–175 附近。
- 这不是可以为了动画绕开的限制。拖入期间应冻结命中区域，只提供不改变窗口几何的视觉反馈；Drop/Leave 完成后再显示收集结果和形态变化。

### 3.4 主题实现与新决定不一致

- 当前 preferences.ts 只读写 dark/light 两种主题。证据：apps/desktop/src/preferences.ts，L34–48。
- 当前 appearance.ts 的 warm-white/navy-black/brand-blue 是悬浮球独立外观设置，并单独写入 localStorage。证据：apps/desktop/src/orb/appearance.ts，L1–5。
- QuickPeek 还把“球体外观”作为独立设置。证据：apps/desktop/src/orb/QuickPeek.tsx，L14–16。
- CSS 当前为白色 root + 深色变量 + 蓝色 primary；尚不是三套完整主题。证据：apps/desktop/src/style.css，L53–77。
- 因此需要将“全局主题”与“球体独立外观”合并为一套三主题状态，并核实多 WebView 同步；不能只改悬浮球色值。

### 3.5 管理中心与辅助面板

- 管理中心当前导航为总览、素材、标签、任务、设置五栏。证据：apps/desktop/src/Manager.tsx，L13、L65–87。
- 总览包含文件架与最近任务；素材页包含名称/标签检索、批量标签和本地规则建议；标签页是标签入口；任务页当前展示最近 20 项复制任务；设置页包含桌面入口偏好、快捷键和两套主题。
- 目标应把总览与标签并入文件与素材；任务中心保留完整历史职责；设置集中启动模式、三主题和桌面偏好。不能把当前“最近 20 项复制任务”误报为统一任务中心已完成。
- App.tsx 当前有多个独立面板状态和多个 Sheet/功能面板入口，包括搜索、AI、互传、系统回收、柠猫回收、重复分析、筛选、复制任务、详情/预览、新建文件架和跨架复制。证据：apps/desktop/src/App.tsx，L126–151、L312–316、L378–395。
- 当前存在单个面板可用的实现，但尚未看到统一的“同一窗口仅一个主要辅助面板”仲裁器；需要状态模型和回归测试，不可仅隐藏按钮。

## 5. 核心用户流程审计

| 场景 | 目标路径 | 当前需要核查/优化 |
|---|---|---|
| 收集文件 | 拖入/粘贴/添加 → 识别当前架引用或复制策略 → 完成反馈 | 明确“添加/收集”，不让用户误以为网络上传 |
| 整理素材 | 选择 → 上下文操作 → 标签/排序/引用复制/移除 | 常用操作就近出现，低频操作收纳 |
| 搜索 | Ctrl+F 当前架 / Ctrl+K 跨架 → 结果 → 预览或打开 | 统一范围和结果呈现，不丢失原筛选 |
| 预览 | 选中 → Space → 退出 → 回到原位置 | 不把预览重新做成第三种窗口形态 |
| 拖出 | 选择/拖动 → 目标接收 → 明确 Copy 语义 | 保留来源；创作软件按其原生导入方式处理 |
| 互传 | 选择文件 → 选择已授权目标 → 确认 → 逐项终态 | 单/多文件与文件夹范围区分；网络授权单独管理 |
| AI | 主动打开 → 查看配置/权限/费用 → 提供必要上下文 → 对话 | 未配置不发请求；不静默上传私人素材 |
| 任务 | 轻量入口显示活动摘要 → 任务中心看完整记录 | 区分复制、传输、AI 的取消/恢复能力 |
| 回收恢复 | 选择对象 → 识别引用/实体/系统回收范围 → 确认 → 反馈 | 不用同一文案混淆移除引用、回收和永久删除 |
| 设置 | 管理中心 → 设置 → 修改主题/启动/桌面偏好 | 所有窗口同步，重启后按设定恢复 |

## 6. 高优先级未决议题

这些问题不重新发起 43 项或 44 项完整问卷。可由技术探针解决的先验证，只有真正改变产品体验的选择才向用户逐项确认。

### P0 · 进入动画实施前

1. **大展开的窗口交接架构**：当前 Orb/Capsule/QuickPeek 在 desktop-entry，Full Shelf 由 main 或 shelf-id 原生窗口承载。需要比较同一 WebView 形变与受控视觉交接两条路线，并证明 OLE 拖放、多架和管理中心不退化。
2. **横向展开的具体交互密度**：最近素材建议 3 项、快速添加、文件架切换、任务摘要和大展开入口是否能在横向尺寸内舒适呈现；必须用真实 125% DPI 原型验证。
3. **形态触发与拖入反馈**：当前单击可展开，hover 主要处理贴边自动隐藏；需要确认是否增加悬停自动展开。技术约束要求拖动期间不改变 OLE 窗口几何，建议拖动时只做视觉高亮，Drop/Leave 后再展开反馈。
4. **直接大展开启动行为**：需要确定启动时打开上次活动文件架还是默认架；没有文件架、上次显示器已断开、窗口位置失效时如何回退。

### P1 · 功能和信息架构收束

5. **管理中心文件与素材栏目**：总览、标签、重复项、回收恢复、文件架管理如何组织为二级内容，既保持三栏又不隐藏高频能力。
6. **任务中心统一边界**：用户界面统一展示哪些任务；复制、LAN 传输、浏览器分享和 AI 各自哪些状态支持取消、重试、暂停或恢复。统一入口不等于统一底层执行器。
7. **三套主题的最终色板**：尤其亮蓝色的主背景、内容表面和文字对比。需要同一屏幕下三主题并排样机，避免亮蓝变成刺眼纯色，也避免退化成“只有按钮是蓝色”。

### P2 · 真实场景闭环

8. **文件夹与拖拽语义**：本地浏览/递归与 P3 网络文件夹传输必须分开定义；外部拖入临时架引用、绑定目录安全复制，拖出到文件夹 Copy，拖到创作软件按原生导入。
9. **AI 和联网边界**：真实模型/费用、素材是否可发往第三方、局域网监听/配对、跨网和手机支持，必须按原有专项授权逐项推进。
10. **发布与恢复**：安装/便携、数据迁移、更新备份、回滚、许可清关、Win10/11 支持范围需在正式发行 Gate 前闭合。

## 7. 推荐推进顺序

1. 完成状态机和窗口交接技术探针，记录精确窗口/尺寸/位置/焦点时间线。
2. 制作 Orb/Capsule/Full 的低保真和高保真原型，优先验证 Capsule 信息密度。
3. 以单面板仲裁和全局三主题 Token 为独立小批次设计。
4. 对核心用户流程做步骤计数和异常恢复检查。
5. 只有文档与原型验收后，才进入业务代码重构；先保留原生文件安全和任务底座。
