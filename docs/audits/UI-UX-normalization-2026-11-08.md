## P2 流程增量及前后对照

接收准备的主路径（进入互传后）由「选位置→开启→阅读地址/指纹和多组复制按钮」改为「选保存位置→开启接收→复制连接信息」，无需填写地址；后续文件请求仍必须接受/拒绝。设备码和保存位置保留，地址/完整证书/单独复制仍在原生details中，可用键盘展开。停止接收与复制连接并列，不隐藏安全退出动作。发送端已有附近设备/配对记忆和一次粘贴，继续复用。

首次截图实际发现就绪后滚动位置继承旧表单，设备码在视口外。增强回归后，三主题均真实失败（viewport ratio 0）；仅在接收状态、方向或面板打开变化时重置接收内容滚动到顶部，连续任务进度更新不触发重置。修复后340×320的设备码、复制和停止三个目标全量可见，地址/证书键盘展开及停止操作仍通过。第一轮局部16项通过；增强滚动回归3项通过9.2秒，最终全量另验。为修复已发现问题中止了一次本地旧构建全量测试；该次不记PASS，远端CI未被取消。

变更仅TransferPanel.tsx、对应CSS与既有测试；状态/命令、配对、TLS、监听、确认/拒绝、取消和终态不变。无Rust、SQLite、Copy/Move、权限、协议或依赖变化。浏览器使用既有harness合成收发状态，不能视为真实LAN或原生收发通过。
