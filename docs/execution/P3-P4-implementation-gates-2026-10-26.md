## Gate 0：上游复用选型（Codex 自主，低风险）

- 固定 LocalSend monorepo 与 protocol 的当前 SHA、版本、许可证，阅读 packages/core/Cargo.toml、模块 API、依赖图、Windows 支持及上游 issues。
- 在隔离 Cargo workspace 编译最小 Rust core（先查看 feature 名；避免无必要 WebRTC/信令），跑其自带测试及静态扫描，不修改主应用 lockfile。
- 如果无法轻量复用，写一份对比：调用 crate vs 严格协议适配 vs 独立进程；记录 API/授权/维护成本。**失败即可停止原方案，不无限研究。**
- 固定 FTS5 / FastEmbed-rs / Ollama 的实际版本、模型权重 license、缓存/下载路径和 SQLite 版本能力；先确认当前应用的数据 schema 及已有 SQL 搜索能力。
- **交付：** 两份最短的技术选型 ADR（P3 与 P4）、上游 SHA+许可清单、可复现实验命令与成功/失败记录。

## Gate 1：P3 LAN 严格离线/受控模拟（Codex 自主测试）

- 在隔离目录写受限 TransferProvider 探针、明确结构的发送/接收事务与任务状态；用合成文件进行双进程 loopback、取消、重名、路径穿越、恶意元数据、临时文件残留和 hash 校验。
- **不对实际局域网广播/监听，不改系统防火墙。** Loopback 的成功明确标记 SIMULATED/LOCAL，不冒称双机 PASS。
- 禁止目录遍历、任意来源路径、静默 Move/Overwrite、未认证明文连接；连接、身份验证、接收根目录和上传授权必须来自受控 Rust 层。
- **交付：** 可复现探针、协议兼容风险表、R3 Gate 申请所需的最小权限表。

## Gate 2：P3 真实双机（用户专项授权）

- 用户明确批准所需 LAN 监听/配对后，进行两台 Windows 的官方 LocalSend ↔ 柠猫互通；再柠猫 ↔ 柠猫。
- 必须实测：发现失败时手工添加、身份确认、接受/拒绝、SHA256 一致、冲突编号、取消、断网与磁盘不足、任务状态、源文件不变与临时产物处理。
- 成果合入前进行文件安全/权限专项 review，精确 EXE/hash 和 CI+双机证据齐备；涉及系统防火墙、新开放端口、真实用户设备数据、正式合并仍须批准。
- **P3 通过线：** 一次真实的受保护双端传输完成，接收端可主动加入文件架；失败不会破坏源或已存在目标。

## Gate 3：P4 本地跨架搜索（可低风险隔离开发）

- 优先使用现有 SQLite 数据；只对**已登记及授权**文件架的名称、标签、类型、来源及失效状态建立可重建索引。
- 对照已有 SQL 查询，评测 FTS5 unicode61 vs trigram；中文 1–2 字采用确定性 fallback，不依赖短 trigram；禁扫全盘。
- 结合 P2 schema 2 软删除/回收/空文件架语义，测试增量更新、迁移备份/WAL、未来版拒写、旧版无法直接读新库的限制。任何修改生产数据库 schema 的 PR 归类 R3，须人工审批。
- **P4-A 通过线：** Ctrl+K 跨架能实际查中/英文名、标签和失效状态，跳转正确架/记录，回收对象处理正确；断电/坏索引后可重建而不破坏原记录。

## Gate 4：P4 可选 AI（需专门费用/隐私授权）

- 在隔离工程测试 FastEmbed-rs 中文模型与可选 Ollama 的 embeddings API，数据仅使用合成文本；实测模型大小、下载行为、延迟、RAM、CPU、许可。
- 默认关闭 AI、无模型下载、无云端 fallback；有无模型都能使用基础全文检索。
- 正式 AiProvider 只能产生候选分类/标签/命名建议，**先展示差异后由用户确认**；真实文件移动/改名/覆盖/上传仍属 R3。
- **P4-B 通过线：** 可选模型真实运行且明确标注来源；未经授权无网络与文件修改；可以关闭并恢复纯本地搜索。

## 节奏与验收口径

- 采用**两个能力流**，避免十几个零碎 PR：P3「网络收发闭环」与 P4「本地检索/可选 AI」；必要时为数据安全及 schema 迁移单独 PR。
- R0/R1 和符合既定规范的局部 R2 可由 Codex 自主测试、复核并依 GitHub 保护规则合规合并。原生拖放、数据、网络监听、权限、正式发布和模型费用自动升级 R3。
- 先完成一个完整功能、一个端到端测试，再扩展。不得复用旧版本 EXE 的原生 PASS 给新包；每个交付附 SHA、CI、Windows 原生状态、已知限制和回滚。
- 不能一次未编译成功就无限改架构；优先减少依赖、复用 Store/Copy/Job、保护小悬浮架。研究不需要截图和重新提问产品定位。
- Gemini 连接 Issue #17 独立跟踪；费用未知前不发模型请求，不阻碍 Codex 主线普通开发。
