# 互传首版统一验收

候选基于已通过的 D15 工作区和扫码交付。解压 Windows 便携测试 ZIP 后，使用随包《使用说明》与两份合成样本。选择测试用法时看设备可达的地址。默认启动器只打开应用，需要用户显式启动本机站点。

## 顺序

| 轮次 | 实际覆盖 |
| --- | --- |
| 五人满员与恢复 | 两端同时发送同名文件，四端同时领取，一端第二块断线后重试，所有落盘重新计算 SHA-256。记录首个进度、吞吐与测试进程峰值内存。[复跑与测量](ROOM-FIVE-MEMBER-LOAD.md) |
| 设备与连接恢复 | 桌面区分本机和 HTTPS 站点，断开期间暂停发送和保存，恢复沿用原邀请。移动端 HTTPS、供件者退出及站点回退各有独立证据与复跑入口。[连接与设备](ROOM-DEVICE-RECOVERY.md) |
| 操作与打包 | 网页断线保留发送文件并显示「续传原文件」。手机浏览器显示「准备保存」，校验后再明确保存。桌面提示先选收件位置，实际收件沿用原生确认。[随包使用说明](../../scripts/transfer-test/使用说明.md) |

## 统一验收清单

1. 用一台电脑打开软件及独立网页，建区时启用审批。确认获批后两端可以查看发件人并互发合成文件。
2. 有可信自托管 HTTPS 地址时，在电脑显示二维码，手机打开同一邀请。批准后双向发送，手机先准备保存，再在下载目录打开文件。
3. 在软件收件目录预置同名样本。确认后检查编号副本及其内容。暂时停站再启动，原邀请仍能打开。
4. 需要五人复测时使用独立浏览器配置。用四名成员加群主填满房间，分别核对两端同发、多人领取和占位释放。

桌面与 Android 的同轮操作、双机网络测试及仍受环境限制的场景按[设备记录](ROOM-DEVICE-RECOVERY.md)核对。正式分发沿用仓库验收。账户、跨账户分享与持续同步按路线图接续。

## 文件卡片与成员标识

临时互传选择文件后显示文件名、大小、图片小图或类型图标。Windows 复用文件架的原生缩略图，网页只对本次选中的图片建立本地预览。接收列表显示类型图标和发件人；成员与发件人使用同一套按成员编号生成的彩色半身头像。名称同时显示，便于辨认。

## 指定收件人

临时互传区的「发送范围」默认是「发给全区」。切到「选择成员」后可勾选一至四位当前成员，发送按钮上方显示具体名字。只有发件人和所选成员看得到、领得到，文件行会标记「指定收件人」。已选成员离群时，发送前需要重新选择。

定向发送使用带分块暂存的新版站点。测试包内的本机站点已启用；自托管站点需更新并开启 `ROOM_BULK_QUOTA_BYTES`。旧站点仍可收发全区文件。两个发送范围的续传记录分别保存，站点未确认范围时不会传输文件字节，旧版站点回退时也看不到已暂存的定向文件。

单机可用软件和独立浏览器配置开出多个身份。例如用软件建群、批准三个网页身份，发送时勾选两名，核对另一个身份的共享列表没有该文件。切回全区再发一个样本，确认三个网页身份都可领取。

## 成员显示名称

站点按互传区检查名称。群主、已加入成员和待批准访客占用名称。首尾空白、大小写和全半角差异仍视为重名。离群、移出或拒绝申请会释放名称。旧会话保留原身份及名称，旧的重名待批准申请遇到在用名称时无法批准。
