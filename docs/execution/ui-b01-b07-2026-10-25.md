## 二、必须交付的七组功能

### UI-B01｜外围黑框、自由拖动、边缘磁吸

解决双眼圆球、胶囊和轻预览外围突兀的矩形黑色容器与阴影。

要求：

1. 移除可见的外围黑色矩形衬底，只保留真实主体边缘极轻微的柔和阴影。
2. 圆球整个可见主体可拖动。
3. 胶囊整个可见非按钮区域可拖动。
4. 轻预览仅顶部标题和非按钮空白区域可拖动。
5. 单击与拖动严格区分，拖动不能误触形态切换。
6. 靠近工作区边缘轻度磁吸，主体始终完整可见并保留小间距。
7. 拖离边缘可重新自由移动，不能自动并入 Dock。
8. 胶囊在四边均保持水平，不旋转眼睛或文字。
9. 适配多屏、DPI、任务栏和窗口真实命中区。

**重点：不能仅用 CSS 把黑色背景设为透明，却继续留下吞噬桌面点击的巨大透明窗口。**

### UI-B02｜双眼微跟随和拖动锁定

沿用原创双眼短线造型，不增加眼白、瞳孔、嘴或猫形装饰。

双眼圆球：

- 鼠标进入圆球附近便轻微注视。
- 两眼朝同一方向，但移动速度和幅度有极小差异。
- 不明显错拍、不夸张变形。
- 鼠标远离自然回正。

胶囊、轻预览和完整文件架：

- 只在对应可见窗口内部感应鼠标。
- 双眼跟随幅度比圆球更小。
- 左上双眼仍然属于非交互品牌装饰。

**所有界面在正式进入窗口拖动状态后，双眼锁定当前姿态；松手后平滑恢复跟随。**

不得为鼠标感应添加大范围不可见点击区域或高成本全局监听。优先复用已有 `OrbMotionController`。

### UI-B03｜轻预览返回与关闭按钮

轻预览右上角包含两个不同操作：

- 返回箭头：轻预览 → 胶囊。
- 关闭 X：轻预览 → 双眼圆球。

两个按钮固定且完整位于轻预览顶部内部。

正常状态仅显示箭头与 X；鼠标靠近时逐渐显示双层圆形结构：精细外轮廓、细间隙和彩色核心。

返回使用克制的蓝色，关闭使用柔和红色。

**无论颜色核心是否出现，整个合法圆形按钮点击区都应可用。**

点击不能造成窗口误拖动，也不能退出软件或删除文件。

### UI-B04｜胶囊连体渐进关闭小球

胶囊不再常驻深色圆形关闭按钮。

鼠标靠近胶囊右上角时，由主体连续、自然地挤出一颗连体小球。

- 初始挤出状态为中性颜色，不出现 X，且不可点击关闭。
- 指针进一步进入中等面积的红色核心时，红色与 X 同步渐显。
- **只有红色核心处于激活状态时才允许关闭。**
- 点击后只从胶囊返回双眼圆球。
- 鼠标离开后小球自然缩回。

胶囊贴靠屏幕顶部或顶部角落时，关闭球自动改为从右下角向下生长。

拖动过程中保持原锚点，松手后根据最终贴边位置平滑切换，不允许两个关闭球同时出现。

### UI-B05｜所有类似滚动条按需显隐

解决当前文件架菜单里常驻的灰色滚动条。

将这一体验统一应用到适合的菜单、列表和滚动容器：

- 平常隐藏明显的轨道和滑块。
- 鼠标靠近边缘或发生实际滚动时逐渐显示。
- 停止滚动、鼠标离开后渐隐。
- 保留可拖动滑块、滚轮、触控板与键盘操作。
- 滚动条出现和消失不能导致内容横向抖动、菜单宽度变化。
- 尊重系统强制显示滚动条和无障碍要求。

优先使用轻量稳定方案，不为此引入大型滚动框架。

### UI-B06｜失效引用修复、清理与双层回收

解决文件被外部移动或删除后，失效卡片一直占用界面的问题。

失效卡片要有直观、轻量的操作，包括：

- 刷新、更新引用。
- 重新定位文件或文件夹。
- 移入柠猫回收站。
- 多选及批量清理。

尽量在文件卡片或现有选择工具栏完成，不强制右键或打开额外管理中心。

必须建立**两套严格分离的回收语义**：

**第一套：柠猫内部回收站。**

仅回收工作站中的文件引用记录，不改动磁盘原文件。支持持久化、撤销、恢复与用户主动清理。

**第二套：Windows 系统回收站。**

提供独立、清楚命名的「移入 Windows 回收站」命令。

允许在用户明确选择、查看完整影响范围并额外确认后，处理绑定目录内的真实文件以及普通引用架指向的外部真实文件。

必须采用真正的 Windows 回收站能力，不得降级为永久删除。

真实文件回收的执行顺序必须是：

1. 校验真实路径与安全边界。
2. 用户明确确认。
3. Windows 实际回收成功。
4. 发起操作的当前文件架卡片自动进入柠猫内部回收站。
5. 其他文件架里指向同一实体的引用继续保留，标记「引用失效」。
6. 标签、排序和关联归属不丢失。

取消、失败或部分成功必须准确反馈，不得提前隐藏未回收成功的卡片。

必须有崩溃/失败后状态恢复方案。Windows 回收与 SQLite 不是单一事务，不能虚构原子成功。

**恢复柠猫内部引用记录并不代表自动恢复 Windows 回收站中的真实文件。**

### UI-B07｜文件架直接回收与完整生命周期

解决创建文件架后无法从当前界面直接删除的问题。

在现有文件架切换菜单中：

- 每个文件架行在 hover 或键盘焦点时露出小型垃圾桶图标。
- 点击行本体仍然切换文件架。
- 点击垃圾桶只将这一文件架移入柠猫内部回收站。
- 不需要右键，也不需要额外打开一层管理窗口。
- 操作后提供轻量「撤销」。

必须支持：

1. 用户新建的文件架可删除。
2. 系统基础文件架「灵感收集」「本次中转」也可删除。
3. 整个文件架连同其中全部文件引用、标签、人工排序一起作为一个整体回收。
4. 整架恢复时一次性还原原有整理结构。
5. 即使删除最后一个文件架也允许成功。
6. 删除全部文件架后显示简洁「暂无文件架」空状态，并提供「新建文件架」「从回收站恢复」。
7. 重启后不能自动创建用户已经删除的基础架。

**柠猫回收站本身采用当前窗口右侧轻量抽屉。**

现有菜单保留简洁的「柠猫回收站」入口。

抽屉默认显示整个工作站的回收记录，可切换为当前文件架筛选；能恢复已删除文件引用，也能整体恢复已删除文件架。

**回收记录默认长期保留，不设置 30 天自动清理机制。** 只有用户主动确认后，才能永久清理软件内部的回收记录。

永久清理软件记录绝不连带删除真实磁盘文件。

必须修复 SQLite 初始化逻辑，避免预置文件架因程序重启被重新插入。

### S2：完成柠猫内部回收闭环

### S3：完成 Windows 原生实体回收

实现独立、安全、额外确认的系统回收操作。

只用自行生成的隔离合成文件测试。

不允许用永久删除模拟 Windows 回收站。

### S4：完整回归与集中样机验收

在同一完整候选中执行 UI-B01～B07 联合验收，以及已有 P0/P1/P2/D-ORB 核心回归。

至少检查：

- 圆球→胶囊→轻预览→完整架→收回入口。
- 三球色与深浅主题。
- 真实窗口拖动与双眼锁定。
- 四边磁吸及顶部关闭球位置。
- 轻预览返回和关闭。
- 滚动条自动显隐。
- 失效引用更新、清理和恢复。
- 文件架直接删除、整架恢复和零架状态。
- 跨文件架引用保留。
- Windows 实体文件回收及失败处理。
- 原生拖入/拖出、绑定目录安全 Copy、不覆盖来源。
- 拖放取消、任务保护、Dock、独立窗口、托盘、重启恢复。

每项都必须标为 PASS、FAIL、BLOCKED 或 NOT TESTED，不能用浏览器模拟替代 Windows 原生测试。

## 四、自主权限与禁止事项

**允许自主完成：**

界面布局、动画参数、轻量滚动条、按钮美术、文案、测试补充、组件整理、低风险错误修复及有充分回归证据的局部优化。

可逆的中低风险问题按仓库授权规范自行审核，不需要为每一个小问题向用户请示。

**可以开发但必须严格保护的 R3：**

涉及 SQLite schema、真实文件、Windows 回收站、原生窗口、拖放目标、任务取消或数据归属的功能，可以在隔离分支编码、使用合成数据进行受控自动测试，但不能未经额外许可在用户真实数据上测试或启用。

不得自动安装、覆盖用户现有程序、修改用户私人数据库、合并高风险 PR 或正式发布。

默认使用后台、无头或云端 CI。用户此前要求不干扰电脑正常使用，因此没有新的明确桌面操作许可时，不得私自打开 Windows 候选、Explorer 或操作鼠标键盘。

真正需要可见 Windows 桌面验收时，集中一次向用户说明，避免反复打断。

不新增付费 API 调用，不扩大到 P3 LAN 或 P4 AI 范围，不擅自重新设计已确认的产品方向。

## 五、工程与回滚要求

继续采用原技术栈：Tauri 2、Rust、React、TypeScript、SQLite、现有 shadcn/Radix 体系。

优先复用现有源码与原生文件工作流。

运行实际仓库支持的检查，包括：

- 仓库规范检查。
- TypeScript / Vite 构建。
- Playwright 浏览器交互测试。
- Rust 单元与集成测试。
- Cargo fmt / Clippy。
- Windows 构建与受控产物核验。
- SQLite integrity 与迁移/恢复测试。
- 合成来源文件和目标文件 SHA256 校验。

特别注意 SQLite WAL：数据库升级前必须使用可靠的一致性备份，不得仅复制主 `.db` 文件就认为已安全备份。旧版二进制是否能读取升级后的 schema 必须明确，代码回滚不代表数据库也能直接回滚。

任何危险操作均不得损坏用户原始素材。
