# 自托管临时互传区网页验收

[产品方案](https://github.com/2539426035852ningmao-cmyk/ningmao-file-workstation/pull/105)已获确认。本批交付网页小文件流程。站点使用 Node HTTP 或 HTTPS、独立 SQLite 数据目录、同源会话及持久暂存，借用现有 React/Vite、三个主题和文件名检查。区内权限与文件清单直接由自托管服务提供。站点暂存路径参考[启动说明](../../apps/web/README.md)。

| 验收项目 | 结果 |
| --- | --- |
| Windows 本机网页构建与自动测试 | 构建通过，Vitest 29 项和 Node 10 项通过。 |
| Windows 本机 Chromium | 16 项通过。新增用例以实际自托管服务启动两份浏览器配置，甲建区、乙提交申请、甲批准、两个方向分别下载，测试读取保存路径并验证长度和独立 SHA-256。发送者撤回后，对方列表移除文件。 |
| 权限与回执 | API 用例覆盖待批准访客和非成员拒绝读取、双向下载内容一致、发送者撤回、旧文件 URL 返回 404。 |
| 两台独立 Windows 客体 | 网页双向收发通过。使用两个独立虚拟磁盘、网卡地址和 Chromium 配置，经同一自托管 HTTPS 站点完成建区、邀请、审批、两个方向的真实落盘及 SHA-256 对照。 |
| 未进入本次验收的场景 | 安装版互联、手机模拟器、公网 Cloudflare、20 GB 和跨端续传。 |

复测使用同一区的两个浏览器，通过链接或邀请码加入。在两个方向各传一份含中文文件名的合成 TXT。记录两个下载文件的 SHA-256、拒收或批准结果及撤回后旧链接状态。新站点限全区分享，单文件 64 MiB、总暂存 512 MiB。指定成员密文、成员设备供件和文件换源属于后续里程碑。新请求在服务端撤回后立即失效，已开始的响应还可能传完。

## 双 Windows 客体实测

2026-11-19，验证应用提交 `c6e514992e5f849546bc6ba013ca10a1f30ac439`。同一台宿主运行 QEMU 11.1.0 软件仿真，两台 Windows 11 Enterprise LTSC 评估客体均报告 `10.0.26100.1742`，分别独立写入虚拟磁盘。站点绑定宿主机回环地址，客体通过虚拟网络使用 HTTPS。Chromium 159 使用各自独立的持久配置。宿主内存有限，两台客体交替启动。发送端关机后由站点暂存供件。[微软评估镜像](https://www.microsoft.com/en-us/evalcenter/download-windows-11-enterprise) · [QEMU 下载来源](https://www.qemu.org/download/)

1. 甲通过网页建区、开启审批、上传合成 TXT 后关机。
2. 乙用同一邀请加入并看到待批准，随后关机。甲重启后仍保有群主权限，在网页批准乙，然后关机。
3. 乙重启后下载甲的文件，计算保存文件的哈希，再从同一房间向甲上传另一份合成 TXT，随后关机。
4. 甲重启后下载乙的文件，计算保存文件的哈希。

| 方向及保存的文件 | 落盘字节 | 接收客体独立计算的 SHA-256，两项均与源一致 |
| --- | ---: | --- |
| 甲 → 乙，`甲到乙.txt` | 20 | `d48d8ebb5186242fd685275bcc91830a3d4ef042afcd3ed8945bb9d3eb518300` |
| 乙 → 甲，`乙到甲.txt` | 20 | `c2b2edfa3f77ff91846ce1fcffa55165bf1e9a9b5b34464e91a1cb040b2cbecb` |

乙首次启动 Chromium 超过 120 秒，重试通过；乙重启后首次请求早于网卡就绪，拿到地址后重试通过。甲重启后一次 HTTPS 请求发现客体时钟偏差，校正客体时钟后通过。客体运行时可用，Windows 首次桌面设置报错；本验收通过设置阶段控制台启动实际 Chromium。普通桌面登录和 Windows 安装包留待安装版阶段验证。拒绝入区和撤回另由本机浏览器及 API 回归覆盖。[网页 CI](https://github.com/2539426035852ningmao-cmyk/ningmao-file-workstation/actions/runs/44375270039)
