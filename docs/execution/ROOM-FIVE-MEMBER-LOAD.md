# 五人文件群并发与恢复验收

五个独立 Chromium 会话经站点回环加入同一房间。群主批准四个成员后，两端同时发送各约 8 MiB 的两份同名合成文件。测试等待两个首块请求一起就绪才放行。四名成员同时领取群主发出的文件。测试等待四个首段同时就绪，并仅中断一名领取者的第二段请求。该成员重试后只重新请求中断的分块，其他三名成员继续完成。

四份落盘文件均与群主源文件 SHA-256 一致。群主也实际保存另一位成员发送的同名文件，哈希与第二份源文件一致。测试再次领取已经校验过的文件，无额外站点分块请求，两份源文件保留原样，站点列表保留两份同名文件。浏览器下载保存至不同的合成路径。目标目录已有同名文件时的原生编号留存及取消清理见[原生 Windows 双机记录](TEMPORARY-ROOM-WINDOWS-GUEST-ACCEPTANCE.md)。

| 测量 | 同一 Windows 宿主三次回环 |
| --- | --- |
| 点击发送至首条可见进度 | 74–78 ms |
| 两端合计上传吞吐 | 9.4–9.8 MiB/s |
| 四端合计下载吞吐 | 35.9–40.5 MiB/s |
| 站点及 Playwright 测试进程合计 RSS | 起始 121 MiB，采样峰值 339–374 MiB |

吞吐从点击到应用完成提示或浏览器下载事件，包含并发放行等待和指定的续传重试。内存以 25 ms 采样，覆盖测试工具、合成缓冲及内嵌站点。Chromium 独立进程内存和真实网络吞吐另测。三次均通过。

```powershell
npm --prefix apps/web run build
npm --prefix apps/web run test:browser -- room-five-member.spec.ts --repeat-each=3 --workers=1
```
