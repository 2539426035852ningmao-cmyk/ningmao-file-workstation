## B. 有真实产品取舍，需要用户在合适时点确认

### D-01 · 首个公开 Windows 交付门槛（**CONFIRMED · 2026-10-26 · 选择 A**）

用户正式选择 **A：分阶段发布**。以明确标识的 **Windows 11 x64 / 未签名 / 仅测试的 Preview** 作为首次公开候选目标，但**必须先完成核心文件安全与该环境 Windows 原生验收**。正式稳定版另外完成所宣称支持平台（长期目标 Win10/Win11）的原生兼容、安装/升级/卸载、数据保护、关键 DPI/多屏和签名/信任策略审核；没有 Win10 证据就不能宣称 Win10 已验收，缩小稳定版支持范围另经确认。

- **用户确认：** “柠猫首个公开测试版本的发布策略选择 A”，2026-10-26。
- **取舍理由：** 允许符合安全底线的 Windows11 x64 预览先用于自愿真实测试，不必等待所有平台全矩阵才能获得反馈；稳定版不降低认证要求。
- **正式发布合同：** [D-01 Windows Preview 与稳定版 Gate](product/D01-windows-preview-release-policy-2026-10-26.md)。
- **执行约束：** 发布策略确认≠现在就能发布；P2 r21 原生仍 PARTIAL，R3、高风险代码合并、签名费用、安装/正式 Release 均需独立批准。原43项/P4独立44项保持不变。

### D-02 · P3 首发是否包含递归文件夹互传（**CONFIRMED · 2026-10-26 · 选择 A**）

用户正式选择 **A：先单文件 + 多文件批量，文件夹后续实现**。P3 LAN 首发应真正支持单个普通文件及手动多选文件组成的批次，逐文件完整性、冲突、不覆盖、取消/断线和部分成功状态必须可验收；**不支持把整个目录及其子目录自动递归发送/保留目录树**。用户选中文件夹时明确提示“不支持发送整个文件夹”，不得自动递归/无提示扁平化或暗中发送其子项。

- **用户确认原话：**“D-02 正式选择：A，先单文件 + 多文件批量，文件夹后续实现（推荐）。”
- **取舍理由：** 先以可运行、无新增服务费且不破坏 P2 文件安全的单/多文件 LAN 闭环取得真机证据；目录递归涉及重解析链接、超深路径和层级冲突，独立安全 Gate 后置。
- **正式范围和验收合同：** [D-02 P3 首版单/多文件范围](product/D02-p3-file-batch-first-scope-2026-10-26.md)。
- **实施边界：** 决策归档不表示 P3 网络互传已经实现、已批准端口监听、已批准发布或获得任何用户真实目录访问权限。

### D-03 · P4 文本搜索结果的隐私呈现（**PENDING · 下一项讨论**）

已明确只扫描授权范围，但搜索结果中是否默认显示文档正文命中片段、敏感路径和离线索引摘要，需要更细的 UI/隐私合同。

- **推荐：** 常态显示文件名、类型、来源/所在架和有限状态；正文摘要/敏感路径通过用户明确展开并通过授权检查才能展示；撤销权限时删除派生内容，避免通知/球体泄漏私人文本。
- **状态：** 仅推荐，不标记为正式冻结决策。

### D-04 · 第三方原生插件开放时机

P4 第29–39项确认分级插件与权限，但不能因此推出「无条件允许任意可执行第三方插件安全沙箱」。

- **推荐：** 优先受限声明式/沙箱化的插件接口，先验证只读 metadata SDK、能力代理和撤权；具有系统原生执行能力的插件单独作为高风险开放计划，明确 Windows 安全隔离技术与失败策略后实施。
- **状态：** 开放时机尚未冻结；先做安全技术验证，不直接允许任意二进制文件接入。

## D. 决策同步协议

对任何 D-xx 产品选择，记录：
1. 用户最终的原话和日期；
2. 曾比较的选项与确定理由；
3. 是否影响 43 项冻结要求、P4 44 项、`design.md` 和权限安全；
4. 更新到 Issue/ADR/路线图；如果改了前端信息架构再更新设计合同；
5. 将决策明确标记为 `CONFIRMED`，而非保留「推荐」；给 Codex 精确可验收条款。

**没有新确认前，继续遵守既有决策，不把待确认问题当阻碍 P2 低风险修复的理由。**
