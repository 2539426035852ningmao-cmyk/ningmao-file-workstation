## B. 有真实产品取舍，需要用户在合适时点确认

### D-01 · 首个公开 Windows 交付门槛（**当前优先讨论，仅此一题**）

虽然 43 项决策已规定 Windows10/11 优先、正式安装版+便携版分阶段，但**首个对外测试包 vs 首个稳定版**的 Win10/Win11 认证范围、签名和未知问题披露粒度没有明确写成一条可操作的发布合同。

建议选择：
- **推荐：** 可以先将真实验收通过的 Windows11 x64 版本以「未签名、仅供测试的 Preview」交付明确知情的测试者；**首个正式稳定版**须完成承诺的 Windows10/11 环境兼容、核心文件操作、安装/卸载/升级安全、签名/信任策略审核和重大未测项处理。无法获得 Win10 真机证据时，不得宣称 Win10 已验收，可缩小首个稳定版宣称范围并另行确认。
- **备选：** 所有对外公开的候选（包含测试预览）也必须先覆盖 Win10/11 完整矩阵，上市更谨慎但反馈速度可能降低。

**当前状态：提案，未获用户选择，不自动发布。** 选择还需遵循已有的 R3 授权、发行/签名许可成本控制。

### D-02 · P3 首发是否包含递归文件夹互传

已有决定锁定 LAN 文件收发的安全闭环，但「整个文件夹递归发送」是否纳入第一轮正式通过线仍不够明确。P2 已有「递归目录 Copy 未支持」历史限制。

- **推荐：** 首版优先单文件/多文件批次的完整安全收发；目录递归、符号链接、特殊权限、超深路径先作为独立复杂 Gate，不以添加上传文件夹入口掩盖未实现的安全语义。
- **状态：** 建议默认最小实现，**如影响 P3 首版对外功能说明则请用户确认**。

### D-03 · P4 文本搜索结果的隐私呈现

已明确只扫描授权范围，但搜索结果中是否默认显示文档正文命中片段、敏感路径和离线索引摘要，需要更细的 UI/隐私合同。

- **推荐：** 常态显示文件名、类型、来源/所在架和有限状态；正文摘要/敏感路径通过用户明确展开并通过授权检查才能展示；撤销权限时删除派生内容，避免通知/球体泄漏私人文本。
- **状态：** 仅推荐，不标记为正式冻结决策。

### D-04 · 第三方原生插件开放时机

P4 第29–39项确认分级插件与权限，但不能因此推出「无条件允许任意可执行第三方插件安全沙箱」。

- **推荐：** 优先受限声明式/沙箱化的插件接口，先验证只读 metadata SDK、能力代理和撤权；具有系统原生执行能力的插件单独作为高风险开放计划，明确 Windows 安全隔离技术与失败策略后实施。
- **状态：** 开放时机尚未冻结；先做安全技术验证，不直接允许任意二进制文件接入。

## D. 决策同步协议

对任何 D-xx 产品选择，记录：
1. 用户最终的原话和日期；
2. 曾比较的选项与确定理由；
3. 是否影响 43 项冻结要求、P4 44 项、`design.md` 和权限安全；
4. 更新到 Issue/ADR/路线图；如果改了前端信息架构再更新设计合同；
5. 将决策明确标记为 `CONFIRMED`，而非保留「推荐」；给 Codex 精确可验收条款。

**没有新确认前，继续遵守既有决策，不把待确认问题当阻碍 P2 低风险修复的理由。**
