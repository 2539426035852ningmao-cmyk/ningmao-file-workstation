## 1. UI-B01～B07：需要一次实现的完整行为合同

### UI-B01 去外围黑框、自由拖动与贴边
- 圆球、胶囊、轻预览必须消除**可见的外围大矩形黑框、深色衬底/矩形阴影**；仅允许贴着可见主体的极弱柔和阴影。Windows HWND 矩形可存在于实现层，但透明空白不能吞掉桌面点击或错误抢 Drop。
- 圆球**整个可见球体**可拖；胶囊**整个可见非功能按钮主体**可拖；短距离单击仍完成原形态切换。轻预览**只允许顶栏标题和非按钮空白区**拖动，文件卡片/正文不成为窗口拖动手柄；完整架维持其已有合法拖动区域。
- 自由拖动带适度边缘磁吸；接近工作区边缘轻吸附后主体**完整可见且有极小间距**，拖离可恢复自由放置，不能自动合并到 Dock。
- 胶囊四边贴靠**始终水平**，眼睛和文字不旋转；Dock 左右竖排/上下横排是另一套规则。位置记忆支持窗口工作区、DPI 与多显示器。
- 关闭小球锚点与磁吸几何、原生 Drop/DragSession 目标和点击命中范围保持安全一致。

### UI-B02 双眼跟随
- 只保留既有**一长一短、斜短线形状的两只眼睛**；不加眼白、瞳孔、猫耳、嘴、表情组件。
- 双眼圆球在鼠标**靠近球但尚未进入球体时**便开始轻微注视：双眼看同一方向，幅度/响应速度存在**极小自然差异**，不明显错拍、不斜视；离开感应范围自然回正。**不得扩大透明 HWND 点击范围**来实现接近检测，不采用昂贵或广泛监控的常驻全局鼠标钩子。
- 胶囊、轻预览、完整架左上双眼**仅在各自可见窗口内部**极轻跟随；外部不感应，离开回正，运动幅度比球更低。它们是非交互装饰，不接管按钮。
- **所有窗口一旦真正进入拖动状态，双眼冻结当前注视姿态，释放后平滑恢复**；单击/拖动有阈值，释放拖动不误触打开/关闭。拖动时不要叠加眨眼导致抖动。
- 复用/改良当前 `OrbMotionController`，隐藏和非活跃低功耗，支持 reduced-motion 与键盘。

### UI-B03 轻预览右上返回/关闭
- **返回箭头**：quick-peek → capsule；**关闭 X**：quick-peek → orb（跳过胶囊）。都不是退出应用或删除记录。
- 两个按钮固定在轻预览**顶部内部**，不越过窗口边界；默认只露箭头和 X，无常驻大圆底/方框。各自 hover/聚焦时连续渐显**相同结构的细圆外缘→窄中性间隙→彩色内核**；返回为蓝，关闭为柔红。
- 两按钮**完整圆形命中区始终可点击**，不需要等彩色内核可见；按钮区不能同时启动窗口拖动。键盘/触摸无 hover 时仍可用。

### UI-B04 胶囊连体渐进关闭球
- 胶囊闲置时不出现常驻的深色关闭圆圈；鼠标接近右侧规定角落时，胶囊本体**连续挤出连体小球**，而非分离悬浮球。指针只控制生长程度，**不改变关闭球左右位置**。
- 默认固定**右上**挤出；胶囊吸附到**屏幕顶部或顶部角落**时改为**右下向下生长**；拖动过程中**锁定此前锚点**，鼠标松开后按最终位置平滑改锚，不能上下双球同时出现。
- 生长的普通中性小球**没有 X、没有红色，也不可关闭**；进入适中的**内部红色核心**后，红填充与 X 同时渐显，**只在红核心激活范围可点击**。离开柔和缩回；没有隐形超大关闭热区。
- 激活后点击仅 capsule → orb，不退出软件、不清空文件架。分清 UI-B03 的按钮全圆可点与 UI-B04 只有红核心可点的语义。

### UI-B05 全局按需显示滚动条
- 截图问题是完整架更多菜单侧边常驻灰色条，但要求尽量统一到所有类似滚动容器。静置时不常驻粗灰轨道；**滚动时、接近滚动边缘、键盘焦点需要时**显示低对比窄滑块，停止后平滑隐藏。
- 保留滚轮/触控板/键盘与拖动滑块能力、可访问性/系统强制滚动条偏好；显隐**不改变菜单宽度、不造成内容横跳**。优先精简 CSS/原生 overlay 能力，避免引入重型滚动库；检验 Win10/11 WebView2 的差异。
- 关注 `ShelfMenu.tsx`、`style.css` 的 `.shelf-menu`、`.file-scroll`、管理中心滚动区。

### UI-B06 失效引用、文件清理、双层回收
- 文件原路径被移动/删除后，旧引用可标「引用失效」但**必须能直接更新、重新定位、清理、批量处理**，不能永久占据界面。优先复用当前 `relocate_reference`、刷新与安全引用操作，并将操作带到卡片选中时的轻量工具条；不要求右键/另开管理窗口。
- 建立**真正持久化的柠猫内部软回收**：默认只隐藏/保留工作站记录，具有撤销、恢复及手动清理，不碰实体文件。原有 `remove_reference` 是普通架 SQL 硬删且绑定架禁止，不可冒充软回收已完成；绑定架失效索引也需支持安全对比和**仅清理记录**。
- 另设名称/位置明确不同的 **「移入 Windows 回收站」**：用户可对**绑定目录内指定文件**和**普通引用架指向的外部真实文件**主动执行，必须额外确认真实路径、数量、目录影响、同源其它架关联及不可恢复情形；使用确实支持回收站的 Windows Shell 机制，**绝不悄悄调用永久删除或在回收不受支持时降级永久删**。不得自动扫描用户私有盘、自动清理源文件或扩大权限。
- 成功的严格顺序：**Windows 针对目标真实文件回收确认成功 → 发起操作的当前架该卡片进入柠猫内部回收站 → 其他架同源引用保留并标记「引用失效」**（原标签、顺序、归属仍保留）。失败/取消保持未完成项目可见。批量部分成功逐项处理，禁止全有全无的虚假提示。
- Windows 回收和 SQLite 不可能组成单一原子事务；用可审计操作状态、幂等协调、崩溃恢复防止双删、误报与丢记录。实体路径重新校验，保护重解析点、符号链接、敏感根目录、共享/离线/不存在路径及源被外部替换的情况。工作站内部恢复引用**不等于** Windows 系统回收站还原真实文件。
- 一份真实文件被多架引用时严禁只看**同名**就更新其它架；基于实际核验的路径和身份判断。已有原生 Copy 安全、绑定文件副本编号、取消和恢复语义不退化。

### UI-B07 文件架直接移除、统一抽屉与整架生命周期
- 文件架切换菜单每行在 hover/键盘焦点时露出极轻垃圾桶（非全行常驻）；点击行仍是切换，点击垃圾桶只作用本行，**无需右键或二级页面**，默认将该架软回收进柠猫回收站，短暂反馈「撤销」。
- 原生预置「灵感收集」「本次中转」、所有新建架及绑定架都可进行**工作站记录级回收**；不删除其真实磁盘目录。可删除**最后一个文件架**，进入安全可操作的「暂无文件架」空状态，仅露**新建文件架／从回收站恢复**，不得自动创建默认架；启动后同样保持零架状态。
- **整架打包回收**：架本身、架内所有引用、标签、手动顺序及可恢复视图信息作为同一逻辑整体进入回收站，显示为一个整架条目，恢复时整体还原，不自动把子项迁往其他架。其它架的同源引用不受此次整架回收影响。
- **右侧轻抽屉**：在现有菜单只留简洁「柠猫回收站」入口；打开后在当前完整窗口右侧查看记录，不新建窗口/管理中心。全局统一数据源，**默认全部**，可筛「当前文件架」，包括已回收文件架；直接恢复/按需手动清理记录。普通删除时无需先开抽屉，撤销在原处完成。
- **软件内部回收记录长期保留**，不使用 30 天自动清空；只有用户主动执行永久清理记录才真正删除记录，且需明确确认。这里的永久清理**只针对软件记录**，**绝不能顺便清空 Windows 回收站或删磁盘文件**。
- **重点源码风险**：当前 SQLite schema=1，在 `Store::open` 中有 `INSERT OR IGNORE` 初始化 ID1/ID2 基础架。必须设计可验证的**数据库 schema 迁移与只在首次使用初始化**机制，避免用户删架后重启又被创建；`shelves/items/jobs` 的外键、唯一约束、任务状态、会话架退出规则、现有 v1-v4 布局恢复和多窗口必须保留。复原整架/多架并发、零架和独立架需一并检查。

## 3. 权限自主分级与快速推进

- **R0 / R1 自主**：布局、品牌眼睛参数、文案/图标、细滚动条、无副作用动画、浏览器无头测试、性能优化、文档、局部回滚和测试证据；发现微瑕疵在本阶段内自己修复。

- **R3 工程可以在隔离分支继续编写与使用合成数据测试**：涉及 SQLite schema、Windows 实体回收、原生窗体生命周期、目标冻结、文件来源、任务取消的变更必须有独立自动测试、对照证据、失败回滚、保护评审；**未经额外授权不得在用户真实数据启用高风险操作、修改原用户数据库、擅自合并到稳定/主分支或安装新候选**。
- 遇硬阻塞只发**一个清楚的问题**；非阻塞的中低风险小问题自己权衡，不每个按钮再询问；不借机扩展 P3 LAN、P4 AI、付费模型、插件生态或第二套设计系统。

## 5. 提交与交付标准
