## 5. 下一批先交付什么

按一次完整用户任务做一个可见的改善，优先 **“选中文件 → 选择发送对象 → 确认结果”** 和 **“找到工具 → 打开 → 返回原任务”**。先观察现有实现，确认真实冗余后再改。

第一批输出一张短表：位置、当前问题、拟删除/合并内容、保留能力、验证方法。无需重审全项目。同步提供一条完整流程的前后对照，随后实现低风险部分，不停留于设计文档。

优先候选（待实际确认，不是已证实缺陷）：

- 重复“发送/互传/浏览器分享”入口是否能按对象统一，技术细节放高级区；不增加第三种通道。
- 未选文件时不出现大量文件操作；选中后直接给适用动作；禁用状态说明原因。
- 工具命名用用户任务，避免 W1、网关、指纹、协议等内部术语成为必读内容；必要安全语义仍清楚。
- 打开已有管理窗口时激活已有实例，保留文件选择、架、滚动和任务上下文；不重复弹多个窗口。
- 减少重复确认和无效返回，常用任务目标不超过三步；真实授权、接收确认、删除或费用步骤不能为凑步数而跳过。
- 精简长说明、重复标题、按钮挤压和溢出，保留键盘、菜单、焦点与无障碍名称。

若必须改变 Rust/SQLite/文件操作/窗口生命周期/传输权限，单独解释必要性、最小范围与回归；不要混进视觉整理。

## 6. 性能：先测一个真实瓶颈，再修一个

用相同硬件、构建类型、窗口状态和合成数据记录前后值，不拿 debug 与 release 直接比较。先测：冷/热启动、首次打开工具、可见/托盘空闲 CPU 与内存、滚动与选择响应、动画空闲开销。记录测量方法与数据规模，不凭感觉宣称提升百分比。

从用户能感知的卡顿开始，按证据选：重复渲染、无变化轮询、不可见窗口动画、重复事件订阅、重复窗口实例、全量列表渲染、过大首包或未释放资源。已有虚拟列表/共享任务/运动控制器优先复用。不要无差别 memo、拆分全项目、换状态库或加缓存层。

单次使用的简单逻辑不为“架构”抽函数；仅抽复用逻辑、复杂步骤或独立概念。入口校验一次，内部类型明确后不重复防御。只处理能说明触发过程并可复现的问题，不为低概率假设堆分支。生成文件改生成器后重生成。

## 7. Figma、网页参考与 Skills 怎么用

本轮尚无用户指定的 Figma 文件链接、file key 或 node。不要猜文件，也不要宣称已经写入 Figma。先查可用连接和用户可访问的设计；若无法确定目标，仅在真正需要写入时问一个目标文件问题，同时继续本地代码观察。

按需使用已安装的 impeccable、creative-desktop-ui-taste、emil-design-eng、Playwright 及对应 Figma Skills；只读所需项，不全装、不为了动效更换技术栈。调用 Figma 的读取、写入、创建文件、组件或动画工具前，遵循该工具对应 Skill 的前置要求。工具不存在或权限不足如实记录。

Figma 先做一条核心流程和可复用组件/变量：沿用 design.md 的主题、尺寸、字阶、间距、图标、圆角、状态与动画参数。不要先制作几十张与程序脱节的图。最终提供文件/节点链接、源码组件对应及差异说明；设计稿不能替代可运行实现。

研究成熟网页交互时，先找与当前问题相似的窄面板、工具菜单、选择/发送、状态反馈或形态过渡。按用户长期顺序查社交反馈→社区→GitHub原始记录→官方资料，已有本机证据优先；无需为纯本地编辑强行检索。比较少量明确案例，记录采用哪个原理、解决什么问题、为什么适合桌面，避免整页照搬。

代码/图标/动画复用必须核对来源、版本或提交、许可证、修改与署名义务；网页可见、Figma可访问都不等于可以复制资产。优先现有 Lucide 和原创双眼 SVG，不引入混杂风格图标包。不得复制 grok-icon-study 的商业提取角色/源码或 aora-bot 未获适当授权的角色资产和受限代码。通用弹簧、插值、状态机原理可独立实现。

动画保持 reduced-motion、隐藏时停止、活跃入口优先；不要持续光晕/粒子/多实例无界 RAF。原生拖放时固定真实接收目标，视觉形变不能改变命中区或文件架身份。

## 9. 验证和交付节奏

集中改动 → 本地相关检查 → 一次有效提交 → 等完整 CI → 处理真实失败。保留 cancel-in-progress，不用频繁推微提交导致 Windows 编译反复取消。源码与受影响行为未变，不反复重打 MSI。

沿用现有命令和测试，不引入第二套测试平台：

```powershell
pwsh -NoProfile -File scripts/check-repository.ps1
# 在 apps/desktop 中：
npm run build:test
npm run test:ui
npm run build
# 在 apps/web 中（仅影响网页时）：
npm test
npm run build
npm run test:browser -- --workers=1
```

Rust/原生变动按 scripts/build-desktop.ps1 现有流程；先读脚本参数与当前工具链配置，不能省正常前端 dist 前置。打包沿用 build-preview-package.ps1 / build-portable-preview.ps1。不要执行 npm run deploy，也不把 dry-run 当实际服务。

先跑受影响用例，再在交付批次做所需全量回归。测试调用真实实现，少 mock、不复制业务逻辑。浏览器视觉、真实 DataChannel、Rust安全I/O、Windows拖放/DPI/多屏、真实跨设备分别记录 PASS/FAIL/PARTIAL/NOT_TESTED。

每批给出：具体少了什么步骤/入口、实际性能前后值、修改文件、原有能力验证、源码完整 SHA、包 SHA、CI链接、未验证项、来源/许可证及回滚。更新 ACTIVE 和必要记忆；功能矩阵由原生成器维护，不手工改生成产物。
