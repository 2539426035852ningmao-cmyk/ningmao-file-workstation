# 柠猫文件工作站 · 阶段路线图

> 2026-10-24 · 方向性规划，不代表已实现 · 仍遵守 43 项冻结决策

## 目标顺序

**快速收集 → 安全复制与整理 → 任意软件间素材流转 → 多设备网络传输 → 经过授权的 AI 检索与修改**。

基础体验从「悬浮球 / 贴边把手」展开为**小型日常文件架**，绝不默认扩展为大型全屏管理台；复杂功能通过按需管理中心承载。应用对外接口与扩展能力先解耦、后启用，不要求 M1 实现全部后端。

| 优先级 | 阶段目标 | 关键行为与验收 | 不纳入当前阶段 |
| --- | --- | --- | --- |
| P0 真实文件基座 | 完成 M1-05/06 安全与精确构建的原生验收 | 引用/绑定、保留来源的 Copy、失败/取消、SQLite 恢复、双击/拖入/拖出真实可用 | 网络与 AI |
| P1 日常小窗 | 340/420/640 场景紧凑化与操作闭环 | 单行顶栏、2–3 列网格、按需搜索/详情/进度、清晰文件状态，保持原生回归 | 固定导航与复杂管理面板 |
| P2 桌面协作 | 多架/悬浮球/贴边柄/智能 Dock、命令/任务入口、管理中心按需打开 | 热区投放、拆出合并、多屏位置记忆、恢复与低资源占用 | 所有能力一次铺开 |
| P3 网络流转 | 先局域网发现与点对点文件发送，再跨网络传递与可选同步 | 权限、加密、冲突、断点恢复、任务中心、离线状态和失败处理 | 未经许可的后台自动同步 |

## 模块边界草案

- **FileReference + AssetIdentity**：独立于路径的身份及版本、离线与重新定位，避免路径变化即丢失分类
- **FileProvider**：本地临时引用、绑定文件夹、未来远程资源，统一只读枚举与用户批准的写入
- **TransferProvider**：LAN、跨网络和同步适配器，与 UI/文件提供器解耦；先有稳定任务和冲突规则
- **CommandRegistry**：同一操作可由 UI、快捷键、未来插件/AI 触发
- **JobQueue + EventBus**：复制、传输、索引、AI 长任务的进度/取消/恢复；插件不可绕开安全检查
- **PermissionBroker**：单次任务/特定资源授权，默认最小权限、可撤销、高风险再确认
- **SearchIndex + AiProvider**：先本地搜索索引，再让用户自行选择云端/本地模型与成本边界

以上是接口方向，不是已存在的模块或具体 SDK 命名。不要提前固定网络协议、云厂商或 AI API，也不要伪称支持热连接；后续通过 ADR/技术试验逐项确定。

## UI 的扩展空间

小文件架的顶栏只保留当前架、搜索、添加与“更多”。设备、任务、AI、插件通过**一个更多入口 + 独立管理中心导航 + 可注册命令**接入；不在悬浮窗为未来功能放一排空按钮。

## 下一关卡需要的用户材料

- **优先**：当前真实 Windows 文件架界面截图，包含完整窗口边界；据此标注应保留、缩小、隐藏或移动的元素
- 可选：用户喜欢的悬浮球、小型浮窗/Dock 参考截图，能看到尺寸与操作感
- 真实 Windows 操作视频仅在需要诊断 drag-out 或缩放错位时再请求
- 不需要用户提供私人文件、凭据、完整磁盘路径或敏感素材，测试优先合成素材

## 状态维护规则

不得将技术探针的验证结果继承给另一份 exe；CI 绿灯不等于系统拖入/拖出、安装、DPI、多屏通过。对于高风险文件操作、正式 UI 方向和主工程重大变更，严格遵守人工验收与 main 保护。完整需求仍保存在 `docs/product-decisions.md`。
