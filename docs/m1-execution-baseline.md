## 2. 已冻结的产品需求

此前已经完成第 1–42 项产品与工程决策，以下为正式需求基线。

### 2.1 文件架类型

**临时文件架**

- 拖入文件默认保存引用，不复制、不移动原文件。
- 默认持久保存文件引用、分组、标签、排序和窗口状态。
- 支持单独创建“仅本次使用”文件架，正常完整退出后清空引用。
- 异常退出不能直接触发不可恢复的数据清理。
- 移除引用不等于删除实体文件。

**真实目录文件架**

- 用户主动选择绑定的本地文件夹。
- 默认逐层浏览，支持递归素材视图。
- 拖入文件默认复制到真实目录，保留来源文件。
- 同名冲突默认自动添加序号，保留两份。
- 支持后续更完善的冲突处理、路径迁移和引用修复。
- 不擅自扫描未授权的磁盘目录。

### 2.2 桌面悬浮系统

- 主窗口多标签。
- 标签可拆为独立悬浮窗口，也可重新合并。
- 文件架可自由移动、置顶、调整尺寸。
- 允许贴边隐藏，或缩成独立悬浮图标。
- 支持鼠标触边、快捷键和文件拖入唤出。
- 多个文件架可收纳进智能 Dock。
- 支持多显示器与不同 DPI 缩放。
- 软件关闭窗口默认隐藏到托盘。
- 默认不开机自启，可自行开启。

### 2.3 素材管理

- 网格、紧凑列表和详细列表。
- 缩略图大小与响应式列数调整。
- 自动排序与手动拖拽排序并存。
- 自定义顺序单独保存。
- 文件可加入虚拟分组及多个标签。
- 支持本地搜索与跨文件架统一搜索。
- 单击选中、空格快速预览、双击使用默认应用打开。
- 按需加载图片、音频和视频预览组件。
- Ctrl+V 粘贴文件或图片。
- 无原始文件路径的截图保存到用户可访问、可配置的本地目录。

### 2.4 文件安全

- 拖出到桌面或其他目录时优先采用安全复制。
- 原始文件移动必须是明确操作。
- 临时引用删除不删除原文件。
- 真实目录中的 Delete 经确认后进入系统回收站。
- 永久删除需要更严格确认。
- 复制和移动过程不得静默覆盖文件。
- 操作失败不得破坏原始数据。
- 设备离线或文件暂时失效时保留引用与分类。
- 支持在用户授权范围内重新定位失效引用。

### 2.5 管理中心

- 悬浮文件架承担日常操作。
- 独立管理中心按需开启。
- 管理中心采用资源管理器与轻量工作台混合布局。
- 左侧导航可收起。
- 中部是主要素材区域。
- 右侧 Inspector 默认隐藏，可按需展开和固定。
- 大窗口使用侧边详情，小窗口使用抽屉。
- 统一深浅双主题，默认蓝色强调色。
- 工具栏采用渐进式设计，不能遮挡拖拽位置。

### 2.6 后续阶段预留

- LocalSend 协议兼容与局域网收发。
- 不同网络的安全文件传输。
- Syncthing 等成熟文件同步能力。
- 多电脑目录访问及共享。
- 浏览器插件。
- AI 分类、重命名、智能检索及外部 API。

这些是架构预留需求，不属于 M1 必须实现的功能。

### M1-04：主工程与设计系统选型

技术选型必须遵守以下原则：

- 原生拖入拖出真实可用是关键门槛。
- 文件数据安全是强制门槛。
- 源码许可证兼容是强制门槛。
- 构建稳定性与可维护性优先于短期开发速度。
- 重视多窗口和未来传输服务的扩展能力。
- 反对重复开发已有成熟功能。
- 避免把多个不兼容 UI 框架长期叠加使用。

若两套技术方案都不能满足关键门槛，则先提交最小技术障碍报告及修复验证方案，不得直接进入大规模功能开发。

用户批准后，只保留一套长期主工程。

### M1-05：第一个真实文件操作闭环

在确定的主工程中实现：

1. 启动一个可移动的悬浮文件架。
2. 从 Windows 资源管理器拖入文件。
3. 默认建立文件引用。
4. 展示真实文件名、类型和图片缩略图。
5. 保存文件架记录到 SQLite。
6. 完全退出后重新启动，恢复持久文件架。
7. 主动绑定一个真实文件夹。
8. 拖入真实文件夹后复制文件，保留来源。
9. 同名时自动安全重命名。
10. 将文件从文件架拖出到支持的 Windows 目标位置。
11. 提供基础复制进度和错误提示。
12. 展示正常文件、失效文件、复制失败等状态。

复杂 Dock、AI、远程传输以及完整管理中心不阻碍这一闭环的验收。

不要为了实现所有视觉效果而拖延真实文件功能。
